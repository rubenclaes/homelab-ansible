# ntfy as an OCI container — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run ntfy as a Proxmox OCI container (vmid 109), reachable at `ntfy.neodata.be`, and have Proxmox send its warnings and errors to it.

**Architecture:** A new role `proxmox_oci` talks to the Proxmox REST API from the controller with the existing `ansible@pve!automation` token, exactly like `proxmox_lxc`: pull the image as a template, create the container, then converge `entrypoint` and `env` (which `create` ignores for OCI templates). A tag `oci` keeps such containers out of `linux` in the dynamic inventory. Proxmox notifications are added to `proxmox_datacenter` the way it already manages backup jobs: `pvesh` as root on pve01, create-or-update.

**Tech Stack:** ansible-core 2.21.4, `ansible.builtin.uri` against the PVE 9.2 API, `pvesh`, ntfy v2.28.0, Caddy (existing role).

**Spec:** `docs/superpowers/specs/2026-09-23-ntfy-oci-design.md`

## Global Constraints

- Image `docker.io/binwiederhier/ntfy:v2.28.0`. Never `latest`.
- Container: vmid `109`, hostname `ntfy`, `192.168.0.32/24`, 1 core, 256 MB, swap 0, rootfs `vm-hdd:2`, `mp0` = `vm-hdd:1,mp=/var/lib/ntfy`, unprivileged, onboot, tag `oci`.
- `PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin` is always the first env entry.
- env is NUL-separated and goes over the API only (`join('\x00')`, verified to survive Ansible and `uri`). Never through a shell or `command` argument.
- `oci-registry-pull` gets `filename` **without** `.tar`; the resulting volid is `local:vztmpl/<basename>_<version>.tar`.
- Proxmox posts to `http://192.168.0.32/homelab` directly, not via Caddy.
- `proxmox-oci.yml` is **not** added to `site.yml`, for the same reason `proxmox-lxcs.yml` is not: it provisions.
- Every task carrying the env, the token or a hash has `no_log: true`.
- FQCN for every module; every task named, capitalised. `ansible-lint` adds no new violations.
- Comments in YAML follow the file they are in. Docs pages are Dutch and explain *why*, not only what (see memory `docs-update-is-a-reflex`).
- `master` is shared: stage by explicit path, never `git add -A`. Commit only when the owner has said to.

## Review Focus

1. **Second run must be a no-op.** If the API returns `env` in another shape than we send (order, separator), every run would rewrite and reboot the container. Test: Task 3 Step 6.
2. **NUL bytes intact at the far end.** A mangled env silently drops `PATH` and the container dies without a message. Test: Task 3 Step 5 checks separate `lxc.environment.runtime` lines, `PATH` first.
3. **A version bump without the flag must not destroy anything.** Test: Task 3 Step 7 runs with a different version and checks the container's uptime is unchanged.
4. **ntfy must not land in `linux`.** Otherwise `site.yml` tries SSH on it and fails the whole converge. Test: Task 1 Step 4 and Task 3 Step 8.
5. **Notifications must arrive when Caddy is down.** Test: Task 5 Step 5 checks the endpoint URL is the IP, not the name.

- [ ] **Step 2: Generate and append the secrets without printing them**

`ntfy user hash` reads the password twice from stdin; OrbStack on the mbp runs the image.

```bash
f=inventory/group_vars/proxmox/vault.yml
img=binwiederhier/ntfy:v2.28.0
rpw=$(openssl rand -base64 24 | tr -d '/+=')
ppw=$(openssl rand -base64 24 | tr -d '/+=')
hash() { printf '%s\n%s\n' "$1" "$1" | docker run --rm -i "$img" user hash 2>&1 | grep -o '\$2[aby]\$[^ ]*'; }
rh=$(hash "$rpw"); ph=$(hash "$ppw")
tok="tk_$(LC_ALL=C tr -dc 'a-z0-9' </dev/urandom | head -c 29)"
[ -n "$rh" ] && [ -n "$ph" ] && [ ${#tok} -eq 32 ] || { echo "generation failed"; exit 1; }
{ ansible-vault decrypt --output - "$f"; printf '\n# ntfy (vmid 109). Het wachtwoord is je login in de ntfy-app; de hashes\n# gaan via env de container in. Het proxmox-account gebruikt alleen het token.\nvault_ntfy_ruben_password: %s\nvault_ntfy_ruben_hash: '"'"'%s'"'"'\nvault_ntfy_proxmox_hash: '"'"'%s'"'"'\nvault_ntfy_proxmox_token: %s\n' "$rpw" "$rh" "$ph" "$tok"; } > /tmp/v.plain \
  && ansible-vault encrypt --encrypt-vault-id infra --output "$f" /tmp/v.plain && rm -f /tmp/v.plain
unset rpw ppw rh ph tok
bin/check-vaulted && echo "still vaulted"
```

The hashes are single-quoted: they contain `$`, which YAML leaves alone but a later edit by hand might not.

- [ ] **Step 3: Add `pve_oci_lxcs` to `lxcs.yml`**

Insert after the last `pve_lxcs` entry (vmid 108), before `drill_vmid`:

```yaml

# Containers uit een OCI-image, gemaakt door roles/proxmox_oci
# (playbooks/proxmox-oci.yml). Apart van pve_lxcs, want die lijst gaat uit van
# Debian, SSH en een baseline, en hier is er niets van dat: één programma uit
# een image, en alles wat het nodig heeft staat in env. De rol zet er tag `oci`
# op, en daardoor houdt de inventory ze buiten `linux`.
#
# `version` is de enige manier om te updaten. Een andere waarde dan wat draait
# geeft een waarschuwing; pas met -e proxmox_oci_recreate=true wordt de
# container opnieuw gebouwd. Dat gooit ook de volumes weg, dus alles wat moet
# overleven hoort in env, niet op de schijf.
pve_oci_lxcs:
  - vmid: 109
    hostname: ntfy
    image: docker.io/binwiederhier/ntfy
    version: v2.28.0
    # Het image heeft ENTRYPOINT ["ntfy"] zonder CMD; kaal start dat de help
    # en stopt meteen.
    entrypoint: ntfy serve
    cores: 1
    memory: 256
    disk: { storage: vm-hdd, size: 2 }
    ip: 192.168.0.32/24
    port: 80
    # Het image heeft deze map niet, en zonder stopt ntfy met "cache database
    # directory does not exist". Wordt meegenomen in de PBS-back-up.
    volumes:
      - { mp: /var/lib/ntfy, storage: vm-hdd, size: 1 }
    env:
      NTFY_BASE_URL: https://ntfy.neodata.be
      NTFY_LISTEN_HTTP: ":80"
      NTFY_BEHIND_PROXY: "true"
      NTFY_CACHE_FILE: /var/lib/ntfy/cache.db
      NTFY_AUTH_FILE: /var/lib/ntfy/user.db
      NTFY_AUTH_DEFAULT_ACCESS: deny-all
      # Voor de iPhone: Apple laat een app alleen via hun eigen push wekken.
      # ntfy.sh stuurt enkel een seintje door, de inhoud haalt de app hier.
      NTFY_UPSTREAM_BASE_URL: https://ntfy.sh
      NTFY_AUTH_USERS: "ruben:{{ vault_ntfy_ruben_hash }}:admin,proxmox:{{ vault_ntfy_proxmox_hash }}:user"
      NTFY_AUTH_ACCESS: "proxmox:homelab:wo"
      NTFY_AUTH_TOKENS: "proxmox:{{ vault_ntfy_proxmox_token }}:proxmox"
```

`roles/proxmox_oci/defaults/main.yml`:

```yaml
---
# The container list is inventory data (`pve_oci_lxcs` in
# inventory/group_vars/proxmox/lxcs.yml), not a role setting. See there for its
# shape and the reasons behind each field.

# Rebuild a container whose running image differs from the declared version.
# Off by default and never on in inventory: a rebuild destroys the container
# AND its volumes. Only the person running it knows the data is disposable.
#
#   ansible-playbook playbooks/proxmox-oci.yml -e proxmox_oci_recreate=true
proxmox_oci_recreate: false

proxmox_oci_node: "{{ inventory_hostname }}"
proxmox_oci_template_storage: local
proxmox_oci_api: "https://{{ pve_api_host }}:8006/api2/json"
proxmox_oci_headers:
  Authorization: "PVEAPIToken={{ pve_api_user }}!{{ pve_api_token_id }}={{ pve_api_token_secret }}"

# Replacing env replaces all of it, PATH included, and an image's own PATH is
# not kept. Without it the entrypoint is not found and the container stops
# without a word. Always first, so a container's env cannot drop it.
proxmox_oci_base_env:
  PATH: /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

`roles/proxmox_oci/tasks/main.yml`:

```yaml
---
# Everything goes through the API with the automation token, from the
# controller, like proxmox_lxc. Setting env and entrypoint needs
# VM.Config.Options; pulling an image needs Datastore.AllocateTemplate. The
# token has both (roles/proxmox_access/defaults/main.yml).
- name: Read the templates on {{ proxmox_oci_template_storage }}
  ansible.builtin.uri:
    url: "{{ proxmox_oci_api }}/nodes/{{ proxmox_oci_node }}/storage/{{ proxmox_oci_template_storage }}/content?content=vztmpl"
    headers: "{{ proxmox_oci_headers }}"
    validate_certs: false
  delegate_to: localhost
  become: false
  register: proxmox_oci_templates

- name: Read the existing guests
  ansible.builtin.uri:
    url: "{{ proxmox_oci_api }}/cluster/resources?type=vm"
    headers: "{{ proxmox_oci_headers }}"
    validate_certs: false
  delegate_to: localhost
  become: false
  register: proxmox_oci_guests

- name: Converge each OCI container
  ansible.builtin.include_tasks: container.yml
  loop: "{{ pve_oci_lxcs | default([]) }}"
  loop_control:
    loop_var: oci
    label: "{{ oci.hostname }}"
```

`roles/proxmox_oci/tasks/wait.yml`:

```yaml
---
# Proxmox answers a create, pull, stop or delete with a task id (UPID) and
# does the work afterwards. Wait for it, and fail on anything but OK - a
# failed pull otherwise shows up two tasks later as "template not found".
- name: Wait for Proxmox task {{ proxmox_oci_upid }}
  ansible.builtin.uri:
    url: "{{ proxmox_oci_api }}/nodes/{{ proxmox_oci_node }}/tasks/{{ proxmox_oci_upid | urlencode }}/status"
    headers: "{{ proxmox_oci_headers }}"
    validate_certs: false
  delegate_to: localhost
  become: false
  register: proxmox_oci_task_status
  until: proxmox_oci_task_status.json.data.status == 'stopped'
  retries: 60
  delay: 5

- name: Require that task to have succeeded
  ansible.builtin.assert:
    that: proxmox_oci_task_status.json.data.exitstatus == 'OK'
    fail_msg: "Proxmox task {{ proxmox_oci_upid }} ended with: {{ proxmox_oci_task_status.json.data.exitstatus }}"
    quiet: true
```

`roles/proxmox_oci/tasks/container.yml`:

```yaml
---
- name: Work out what {{ oci.hostname }} should be
  ansible.builtin.set_fact:
    proxmox_oci_template: "{{ oci.image | basename }}_{{ oci.version }}"
    proxmox_oci_volid: "{{ proxmox_oci_template_storage }}:vztmpl/{{ oci.image | basename }}_{{ oci.version }}.tar"
    proxmox_oci_description: "image: {{ oci.image }}:{{ oci.version }}"
    proxmox_oci_exists: "{{ oci.vmid in (proxmox_oci_guests.json.data | map(attribute='vmid') | list) }}"
    proxmox_oci_volumes: >-
      {%- set m = {} -%}
      {%- for v in oci.volumes | default([]) -%}
      {%-   set _ = m.update({'mp' ~ loop.index0: v.storage ~ ':' ~ v.size ~ ',mp=' ~ v.mp}) -%}
      {%- endfor -%}
      {{ m }}

- name: Work out the env for {{ oci.hostname }}
  ansible.builtin.set_fact:
    proxmox_oci_env: >-
      {{ proxmox_oci_base_env | combine(oci.env | default({})) | dict2items
         | map(attribute='key')
         | zip(proxmox_oci_base_env | combine(oci.env | default({})) | dict2items | map(attribute='value') | map('string'))
         | map('join', '=') | join('\x00') }}
  no_log: true

# --- the image ------------------------------------------------------------
# `filename` without .tar: Proxmox appends it itself, and given `x.tar` makes
# `x.tar.tar`.
- name: Pull {{ oci.image }}:{{ oci.version }}
  ansible.builtin.uri:
    url: "{{ proxmox_oci_api }}/nodes/{{ proxmox_oci_node }}/storage/{{ proxmox_oci_template_storage }}/oci-registry-pull"
    method: POST
    headers: "{{ proxmox_oci_headers }}"
    body_format: form-urlencoded
    body:
      reference: "{{ oci.image }}:{{ oci.version }}"
      filename: "{{ proxmox_oci_template }}"
    validate_certs: false
  delegate_to: localhost
  become: false
  register: proxmox_oci_pull
  when: proxmox_oci_volid not in (proxmox_oci_templates.json.data | map(attribute='volid') | list)
  changed_when: true

- name: Wait for the pull
  ansible.builtin.include_tasks: wait.yml
  vars:
    proxmox_oci_upid: "{{ proxmox_oci_pull.json.data }}"
  when: proxmox_oci_pull is not skipped

# --- version drift --------------------------------------------------------
- name: Read the description of {{ oci.hostname }}
  ansible.builtin.uri:
    url: "{{ proxmox_oci_api }}/nodes/{{ proxmox_oci_node }}/lxc/{{ oci.vmid }}/config"
    headers: "{{ proxmox_oci_headers }}"
    validate_certs: false
  delegate_to: localhost
  become: false
  register: proxmox_oci_before
  when: proxmox_oci_exists | bool
  no_log: true

- name: Decide whether {{ oci.hostname }} runs another version
  ansible.builtin.set_fact:
    proxmox_oci_drift: >-
      {{ (proxmox_oci_exists | bool)
         and ((proxmox_oci_before.json.data.description | default('') | trim) != proxmox_oci_description) }}

- name: Say so when the version differs and may not be rebuilt
  ansible.builtin.debug:
    msg: >-
      {{ oci.hostname }} runs '{{ proxmox_oci_before.json.data.description | default('?') | trim }}',
      inventory says '{{ proxmox_oci_description }}'. Nothing changed. Rebuilding
      destroys the container and its volumes; re-run with
      -e proxmox_oci_recreate=true when that is what you want.
  when:
    - proxmox_oci_drift | bool
    - not (proxmox_oci_recreate | bool)

- name: Rebuild {{ oci.hostname }} on the new version
  when:
    - proxmox_oci_drift | bool
    - proxmox_oci_recreate | bool
  block:
    - name: Stop {{ oci.hostname }}
      ansible.builtin.uri:
        url: "{{ proxmox_oci_api }}/nodes/{{ proxmox_oci_node }}/lxc/{{ oci.vmid }}/status/stop"
        method: POST
        headers: "{{ proxmox_oci_headers }}"
        validate_certs: false
      delegate_to: localhost
      become: false
      register: proxmox_oci_stop
      changed_when: true

    - name: Wait for the stop
      ansible.builtin.include_tasks: wait.yml
      vars:
        proxmox_oci_upid: "{{ proxmox_oci_stop.json.data }}"

    - name: Destroy {{ oci.hostname }} and its volumes
      ansible.builtin.uri:
        url: "{{ proxmox_oci_api }}/nodes/{{ proxmox_oci_node }}/lxc/{{ oci.vmid }}?purge=1&destroy-unreferenced-disks=1"
        method: DELETE
        headers: "{{ proxmox_oci_headers }}"
        validate_certs: false
      delegate_to: localhost
      become: false
      register: proxmox_oci_destroy
      changed_when: true

    - name: Wait for the destroy
      ansible.builtin.include_tasks: wait.yml
      vars:
        proxmox_oci_upid: "{{ proxmox_oci_destroy.json.data }}"

    - name: Treat {{ oci.hostname }} as missing from here on
      ansible.builtin.set_fact:
        proxmox_oci_exists: false

# --- the container --------------------------------------------------------
# env and entrypoint are NOT passed here: for an OCI template Proxmox ignores
# them and copies the image's. They are set in the next section.
- name: Create {{ oci.hostname }}
  ansible.builtin.uri:
    url: "{{ proxmox_oci_api }}/nodes/{{ proxmox_oci_node }}/lxc"
    method: POST
    headers: "{{ proxmox_oci_headers }}"
    body_format: form-urlencoded
    body: >-
      {{ {
           'vmid': oci.vmid,
           'hostname': oci.hostname,
           'ostemplate': proxmox_oci_volid,
           'cores': oci.cores,
           'memory': oci.memory,
           'swap': 0,
           'rootfs': oci.disk.storage ~ ':' ~ oci.disk.size,
           'net0': 'name=eth0,bridge=' ~ pve_lxc_defaults.bridge ~ ',ip=' ~ oci.ip ~ ',gw=' ~ pve_lxc_defaults.gateway,
           'unprivileged': 1,
           'onboot': 1,
           'tags': 'oci',
           'description': proxmox_oci_description,
         } | combine(proxmox_oci_volumes) }}
    validate_certs: false
  delegate_to: localhost
  become: false
  register: proxmox_oci_create
  when: not (proxmox_oci_exists | bool)
  changed_when: true

- name: Wait for the create
  ansible.builtin.include_tasks: wait.yml
  vars:
    proxmox_oci_upid: "{{ proxmox_oci_create.json.data }}"
  when: proxmox_oci_create is not skipped

# --- entrypoint and env ---------------------------------------------------
- name: Read the live config of {{ oci.hostname }}
  ansible.builtin.uri:
    url: "{{ proxmox_oci_api }}/nodes/{{ proxmox_oci_node }}/lxc/{{ oci.vmid }}/config"
    headers: "{{ proxmox_oci_headers }}"
    validate_certs: false
  delegate_to: localhost
  become: false
  register: proxmox_oci_live
  no_log: true

- name: Compare entrypoint and env for {{ oci.hostname }}
  ansible.builtin.set_fact:
    proxmox_oci_config_differs: >-
      {{ proxmox_oci_live.json.data.entrypoint | default('') != oci.entrypoint
         or proxmox_oci_live.json.data.env | default('') != proxmox_oci_env }}
  no_log: true

# Over the API because env is NUL-separated, and no command-line argument can
# carry a NUL. Form-encoding sends it as %00; Proxmox writes one
# lxc.environment.runtime line per entry.
- name: Set entrypoint and env on {{ oci.hostname }}
  ansible.builtin.uri:
    url: "{{ proxmox_oci_api }}/nodes/{{ proxmox_oci_node }}/lxc/{{ oci.vmid }}/config"
    method: PUT
    headers: "{{ proxmox_oci_headers }}"
    body_format: form-urlencoded
    body:
      entrypoint: "{{ oci.entrypoint }}"
      env: "{{ proxmox_oci_env }}"
    validate_certs: false
  delegate_to: localhost
  become: false
  when: proxmox_oci_config_differs | bool
  changed_when: true
  no_log: true

# --- running --------------------------------------------------------------
- name: Read the state of {{ oci.hostname }}
  ansible.builtin.uri:
    url: "{{ proxmox_oci_api }}/nodes/{{ proxmox_oci_node }}/lxc/{{ oci.vmid }}/status/current"
    headers: "{{ proxmox_oci_headers }}"
    validate_certs: false
  delegate_to: localhost
  become: false
  register: proxmox_oci_state

# env is read at start, so a changed env on a running container means a
# reboot. A stopped container is started either way: onboot says it should run.
- name: Start or reboot {{ oci.hostname }}
  ansible.builtin.uri:
    url: >-
      {{ proxmox_oci_api }}/nodes/{{ proxmox_oci_node }}/lxc/{{ oci.vmid }}/status/{{
         'start' if proxmox_oci_state.json.data.status != 'running' else 'reboot' }}
    method: POST
    headers: "{{ proxmox_oci_headers }}"
    validate_certs: false
  delegate_to: localhost
  become: false
  register: proxmox_oci_power
  when: proxmox_oci_state.json.data.status != 'running' or (proxmox_oci_config_differs | bool)
  changed_when: true

- name: Wait for the start
  ansible.builtin.include_tasks: wait.yml
  vars:
    proxmox_oci_upid: "{{ proxmox_oci_power.json.data }}"
  when: proxmox_oci_power is not skipped

- name: Wait for {{ oci.hostname }} to listen
  ansible.builtin.wait_for:
    host: "{{ oci.ip | split('/') | first }}"
    port: "{{ oci.port }}"
    timeout: 60
  delegate_to: localhost
  become: false
  when: oci.port is defined
```

      {{ hook.headers | dict2items

    loop_var: hook

---

## Geval 4 — Een OCI-container

Sinds Proxmox 9.1 kan een Docker-image rechtstreeks een container worden,
zonder Docker ertussen. Er zit geen Debian in, geen SSH en geen apt: alleen
het programma. Proxmox noemt dit nog een tech preview.

**Wanneer wel:** voor iets kleins dat moet blijven werken als de docker-VM
plat ligt. `ntfy` is het voorbeeld: wie meldt dat de docker-VM stuk is, mag er
niet zelf op draaien.

**Wanneer niet:** voor al de rest. Iets met meerdere containers (Immich), of
iets waarvan de data belangrijk is, hoort op de docker-host. Daar heb je
compose, healthchecks en `docker compose pull`.

<Steps>

### Zet hem in `pve_oci_lxcs`

In `inventory/group_vars/proxmox/lxcs.yml`, met een vaste `version`, nooit
`latest`. Kijk naar `ntfy` als voorbeeld. Twee dingen die je bij een nieuw
image moet nakijken:

- **`entrypoint`**: veel images hebben een `ENTRYPOINT` zonder argumenten.
  Kaal start dat de help en stopt meteen, zonder melding.
- **`volumes`**: elke map waar het programma naar schrijft en die niet in het
  image zit. Ontbreekt er een, dan stopt de container.

Zet alles wat moet blijven bestaan in `env`, niet op de schijf. Zie
[Updaten](#updaten-is-opnieuw-bouwen).

### Bouw hem

```bash
ansible-playbook playbooks/proxmox-oci.yml
```

De rol haalt het image op, maakt de container, zet `entrypoint` en `env`, en
start hem. Een tweede run doet niets.

### Geef hem een naam (optioneel)

Zoals bij geval 1, in `caddy_sites`. De container staat na de eerste run in
de inventory, onder `appliances`.

</Steps>

### Waarom anders dan een gewone container

- **Geen `new-guest.yml`**: er is geen SSH, dus geen bootstrap en geen
  baseline. De tag `oci` houdt hem buiten `linux`, anders zou `site.yml` er
  vergeefs de baseline op proberen.
- **`env` gaat via de API, niet via `pct`**: Proxmox wil de variabelen
  gescheiden door NUL-tekens, en een shell kan die niet doorgeven. Alles plakt
  dan aan elkaar, `PATH` verdwijnt, en de container stopt zonder uitleg.
- **Proxmox negeert `entrypoint` en `env` bij het aanmaken** en neemt die van
  het image over. Daarom zet de rol ze er achteraf op, en herstart hij de
  container als ze veranderen.

### Updaten is opnieuw bouwen

Een OCI-container kun je niet `apt upgrade`n. Je hoogt `version` op en
bouwt hem opnieuw:

```bash
ansible-playbook playbooks/proxmox-oci.yml                             # waarschuwt alleen
ansible-playbook playbooks/proxmox-oci.yml -e proxmox_oci_recreate=true
```

Zonder de vlag waarschuwt de rol alleen. Met de vlag sloopt hij de container
**en zijn volumes**. Daarom staat alles wat moet overleven in `env`: voor ntfy
zijn dat de gebruikers, rechten en tokens. Wat je verliest is de berichtcache
van de laatste uren.

### ntfy op je iPhone

Installeer de app **ntfy**. Onder Instellingen → Standaardserver:
`https://ntfy.neodata.be`, gebruiker `ruben`. Het wachtwoord staat in de vault:

```bash
ansible-vault view inventory/group_vars/proxmox/vault.yml | grep ntfy_ruben_password
```

Abonneer op het topic `homelab`. Proxmox stuurt daar zijn waarschuwingen en
fouten heen, rechtstreeks naar `192.168.0.32` en dus niet via Caddy: een
melding over een storing mag niet afhangen van Caddy of AdGuard.

Buitenshuis zonder VPN krijg je wel het seintje, maar kan de app de inhoud
niet ophalen. `ntfy.neodata.be` is alleen thuis of via de VPN bereikbaar.
