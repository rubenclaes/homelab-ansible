# Toestellen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record every device in the house that Ansible cannot log into, guard the list with an assert, and publish it as a generated page.

**Architecture:** A plain mapping in `inventory/group_vars/all/devices.yml`, the same shape as `pve_lxcs` and `caddy_sites`. One assert in `playbooks/docs.yml` validates it against the inventory before anything renders. One Jinja template turns it into `content/technisch/toestellen.mdx`. Nothing outside the repo is touched: the router keeps handing out addresses, and `ip` records the reservation rather than enforcing it.

**Tech Stack:** ansible-core 2.21.4, Jinja2, Nextra 4.5.0 (pinned), existing `playbooks/docs.yml` pipeline.

**Spec:** `docs/superpowers/specs/2026-09-22-devices-design.md`

## Global Constraints

- `ansible-lint` must introduce **no new** violations. Two already exist on clean `master` (`playbooks/new-service.yml`, `roles/docker_stacks/defaults/main.yml`) and are out of scope.
- `ansible-playbook --syntax-check playbooks/docs.yml` must pass.
- FQCN for every Ansible module. Every task named, starting with a capital letter.
- **Comments inside `devices.yml` are English**, matching `lxcs.yml` and `vms.yml`. **Reader-facing page copy is Dutch**, with English technical nouns left English.
- No new npm dependencies. `docs-site/package.json` and `docs-site/next.config.mjs` untouched.
- `roles/adguard/` is **not** touched. Managing AdGuard's rewrites is part 2 and has its own spec.
- The router is not touched. `ip` is a record of a reservation, never an enforcement.
- `master` is shared with another stream of work. Stage by explicit path; never `git add -A`.

### Task 1: The list and the assert that guards it

**Files:**
- Create: `inventory/group_vars/all/devices.yml`
- Modify: `playbooks/docs.yml` — one new task, after the existing directory assert

**Interfaces:**
- Produces: `devices`, a mapping keyed by a short device slug. Each value has `owner` (str), `type` (str), `mac` (str, lowercase colon-separated) and optionally `ip` (str) and `note` (str). Task 2 renders exactly these five fields.
- `devices` lives in `group_vars/all`, so it resolves in the `localhost` play with no `hostvars` indirection. Verified with `ansible localhost -m debug -a var=devices`.

- [ ] **Step 1: Write the data file**

`inventory/group_vars/all/devices.yml`:

```yaml
---
# Everything in the house that Ansible cannot log into: phones, tablets, the
# TV, the printer, the parents' PC. Machines with SSH live in the inventory
# and stay there - one fact, one place.
#
# The MAC is the identifier, not the IP. Same reason pve_vms records them: a
# new MAC means a new DHCP lease. The router at 192.168.0.1 hands out the
# addresses; `ip` here is the reservation set there, written down so a rebuilt
# router can be put back the way it was. Nothing in this repo enforces it.
#
# A device with no reservation simply has no `ip`. That is normal for a guest's
# phone and is not a gap.
#
# MACs are lowercase with colons. docs.yml asserts the form, so two spellings
# cannot become two devices.
devices:
  iphone-ruben:
    owner: Ruben
    type: phone
    mac: "aa:bb:cc:dd:ee:ff"
    ip: 192.168.0.60

  tv-woonkamer:
    owner: gedeeld
    type: tv
    mac: "11:22:33:44:55:66"
    ip: 192.168.0.70
    note: "Chromecast ingebouwd; praat met Plex"

  printer:
    owner: gedeeld
    type: printer
    mac: "77:88:99:aa:bb:cc"
```

These three are placeholders with invented MACs. The owner replaces them with real devices; that is explicitly not part of this work.

- [ ] **Step 2: Add the assert**

In `playbooks/docs.yml`, immediately after the existing task named
`Check the directory against the routes it claims`:

```yaml
    # A reserved address that collides with a managed host is the failure worth
    # catching: put the printer on caddy's address and you find out when DNS
    # stops working, not before. The other three checks keep the list itself
    # honest - one spelling per MAC, no duplicates, no two devices on one IP.
    - name: Check the device list against the inventory
      ansible.builtin.assert:
        that:
          - devices.values() | list | selectattr('mac', 'match', mac_re) | list | length == devices | length
          - devices.values() | list | map(attribute='mac') | list | length
            == devices.values() | list | map(attribute='mac') | unique | list | length
          - device_ips | length == device_ips | unique | list | length
          - device_ips | intersect(inventory_ips) | length == 0
        fail_msg: >-
          devices.yml is wrong.
          Bad or uppercase MAC: {{ devices | dict2items
            | rejectattr('value.mac', 'match', mac_re) | map(attribute='key') | join(', ') | default('none', true) }}.
          Address also used by a managed host: {{ device_ips | intersect(inventory_ips) | join(', ') | default('none', true) }}.
        success_msg: "{{ devices | length }} devices, no address collisions."
      vars:
        mac_re: '^([0-9a-f]{2}:){5}[0-9a-f]{2}$'
        device_ips: "{{ devices.values() | list | selectattr('ip', 'defined') | map(attribute='ip') | list }}"
        inventory_ips: "{{ groups['all'] | map('extract', hostvars, 'ansible_host') | select('defined') | list }}"
```

Every filter chain above was run against this inventory before this plan was written; `inventory_ips` resolves to 10 addresses and `intersect` correctly flags `192.168.0.25`.

### Task 2: The generated page

**Files:**
- Create: `playbooks/templates/docs/toestellen.md.j2`
- Modify: `playbooks/docs.yml` — one render task
- Modify: `docs-site/content/technisch/_meta.js` — one key
- Generated: `docs-site/content/technisch/toestellen.mdx`

**Interfaces:**
- Consumes: `devices` from Task 1, with fields `owner`, `type`, `mac`, and optional `ip` and `note`.
- Produces: the URL `/technisch/toestellen/`.

- [ ] **Step 1: Write the template**

`playbooks/templates/docs/toestellen.md.j2`:

```jinja
---
title: Toestellen
---

import { Callout } from 'nextra/components'

{# Flattened to a list of rows first, so groupby has a plain attribute to work
   on and the table loop does not need to know that `devices` is a mapping.
   dictsort makes the order within a type deterministic; groupby sorts the
   types themselves, so a second run produces no diff. -#}
{% set rows = [] -%}
{% for name, d in devices | dictsort -%}
{% set _ = rows.append({
     'name': name,
     'owner': d.owner,
     'type': d.type,
     'mac': d.mac,
     'ip': d.ip | default(''),
     'note': d.note | default('')
   }) -%}
{% endfor %}

# Toestellen

<Callout type="warning">
Gegenereerd uit `devices` in `inventory/group_vars/all/devices.yml`.
Machines mét SSH staan onder [Hosts](/technisch/hosts/) — die komen uit de
inventory, niet uit deze lijst.
</Callout>

Adressen zijn reserveringen in de router, geen metingen. De lijst legt vast wat
er hoort te staan; niets hier dwingt het af.

{% for type, group in rows | groupby('type') %}
## {{ type }}

| Toestel | Van wie | MAC | Adres |
| --- | --- | --- | --- |
{% for r in group -%}
| **{{ r.name }}** | {{ r.owner }} | `{{ r.mac }}` | {{ ('`' ~ r.ip ~ '`') if r.ip else '—' }} |
{% endfor %}
{% for r in group if r.note -%}
{{ r.name }} — {{ r.note }}
{% endfor %}
{% endfor %}
```
