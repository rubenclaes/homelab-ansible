# Van niets naar alles

Gebruik deze pagina als je vanaf nul begint: een laptop die deze repo nog nooit
gezien heeft, of een `pve01` die opnieuw geïnstalleerd is.

## Welk geval ben jij?

| Jouw situatie | Voorbeeld | Ga naar |
| --- | --- | --- |
| Je wil vanaf een **nieuwe laptop** playbooks draaien | nieuwe MacBook, of de `mbp` opnieuw geïnstalleerd | [Geval 1 — Nieuwe laptop klaarzetten](#geval-1--nieuwe-laptop-klaarzetten) |
| De **`ansible`-sleutel is weg** en er is nergens nog een kopie | laptop kwijt, niet in de wachtwoordkluis | [Geval 2 — De ansible-sleutel is kwijt](#geval-2--de-ansible-sleutel-is-kwijt) |
| **`pve01` is opnieuw geïnstalleerd** en alles moet terug | bootschijf dood, Proxmox van USB teruggezet | [Geval 3 — pve01 opnieuw opbouwen](#geval-3--pve01-opnieuw-opbouwen) |

<Callout type="warning">
Geval 3 zonder geval 1 gaat niet. Zonder sleutel en vault-wachtwoorden begint
daar niets.
</Callout>

### Woorden die je nodig hebt

**Vault-wachtwoord** — ontgrendelt de versleutelde bestanden in de repo. Er zijn er twee: `infra` en `stacks`.

**API-token** — de login waarmee Ansible aan Proxmox vraagt welke machines er zijn.

**Dynamische inventory** — `inventory/homelab.proxmox.yml`: haalt de lijst guests live uit Proxmox, via dat token.

**Bootstrap** — de eerste keer inloggen als root en de gebruiker `ansible` aanmaken.

**Baseline** — de basisinstellingen die elke Linux-host krijgt (o.a. inloggen met wachtwoord uit).

## Geval 1 — Nieuwe laptop klaarzetten

<Steps>

### Haal de repo binnen

```bash
git clone https://github.com/rubenclaes/homelab-ansible.git ~/Development/homelab-ansible
cd ~/Development/homelab-ansible
```

### Installeer Ansible

```bash
pipx install "ansible-core==2.21.4" "ansible-lint==26.8.0"
pipx inject ansible-core proxmoxer requests   # nodig voor de dynamische inventory
ansible-galaxy collection install -r collections/requirements.yml
```

De versies staan vast in `requirements.txt`, dezelfde als in CI.

<Callout type="info">
Zo kan het ook, en zo staat het nu op de `mbp`: `brew install ansible ansible-lint`.
Die `ansible` bevat ansible-core 2.21.4 én `proxmoxer`.
</Callout>

<Callout type="warning">
Zonder `proxmoxer` ziet Ansible alleen `pve01` en de Macs. De guests
(`caddy`, `docker`, …) ontbreken dan, zonder duidelijke fout.
</Callout>

### Kopieer de ansible-sleutel

```bash
scp <oude-mac>:'~/.ssh/ansible_ed25519*' ~/.ssh/
chmod 600 ~/.ssh/ansible_ed25519
```

Staat ook in de wachtwoordkluis. Het pad `~/.ssh/ansible_ed25519` staat vast
in `ansible.cfg`: niet hernoemen.

<Callout type="error">
Maak deze sleutel **niet** opnieuw aan. Elke host kent de bestaande. Echt
kwijt? Zie [geval 2](#geval-2--de-ansible-sleutel-is-kwijt).
</Callout>

### Zet de twee vault-wachtwoorden neer

```bash
mkdir -p ~/.ansible
install -m 600 /dev/null ~/.ansible/vault_pass_infra
install -m 600 /dev/null ~/.ansible/vault_pass_stacks
$EDITOR ~/.ansible/vault_pass_infra     # plak het infra-wachtwoord
$EDITOR ~/.ansible/vault_pass_stacks    # plak het stacks-wachtwoord
```

Plakken zonder spaties erachter: een spatie of extra regel maakt er een ander
wachtwoord van. `bin/vault-pass-client` leest deze twee bestanden.

### Zet de pre-commit hook aan

```bash
git config core.hooksPath .githooks
```

Git doet dit niet zelf bij een clone. De hook blokkeert een commit met een
onversleuteld geheim erin.

### Test

```bash
bin/check-vaulted       # alles wat versleuteld moet zijn, is het
ansible-lint            # de repo is in orde
ansible all -m ping     # elke host antwoordt
```

### Zet je dotfiles

```bash
ansible-playbook playbooks/dotfiles.yml   # daarna werkt `ssh pve01`, `ssh caddy`, …
```

Dit schrijft voor host `mbp`. Meer in [Werkplek](/technisch/runbooks/werkplek/).

</Steps>

<Callout type="info">
Wil je ook `docs.yml` draaien? Dat bouwt de site op je laptop met `npm`, dus
je hebt Node.js nodig. Wil je diensten toevoegen, clone dan ook de
`containers`-repo naar `~/Development/containers`; `new-service.yml` schrijft
daarheen.
</Callout>

## Geval 2 — De ansible-sleutel is kwijt

Alleen als er echt nergens nog een kopie is: niet op een andere Mac, niet in
de wachtwoordkluis.

<Callout type="error">
`-u root -k` (inloggen met wachtwoord) helpt je hier **niet**. De baseline zet
`PasswordAuthentication no`, dus elke host weigert wachtwoorden. Je komt er
alleen nog in via de hypervisor of de console.
</Callout>

<Steps>

### Maak een nieuwe sleutel

```bash
ssh-keygen -t ed25519 -f ~/.ssh/ansible_ed25519 -C "ansible@homelab"
```

### Zet hem in elke container

Als root op `pve01` (via het Proxmox-scherm → Shell), per container:

```bash
pct exec <vmid> -- tee -a /home/ansible/.ssh/authorized_keys <<< "<inhoud van ansible_ed25519.pub>"
```

De vmids staan in `inventory/group_vars/proxmox/lxcs.yml` (104 semaphore,
106 caddy, 107 adguard, 108 tailscale).

### Zet hem in de VM's, pve01 en de Mac mini

- **VM's** (`pbs`, `docker`, `docker-grafana-stack`): via de console in het
  Proxmox-scherm, in `/home/ansible/.ssh/authorized_keys`.
- **`pve01`** zelf: via de Shell in het Proxmox-scherm, zelfde bestand.
- **`macmini`**: Ansible logt daar in als `rubenclaes`, dus in
  `~/.ssh/authorized_keys` van die gebruiker.

### Zet de nieuwe publieke sleutel in de inventory

```bash
$EDITOR inventory/group_vars/proxmox/lxcs.yml   # pve_lxc_defaults.pubkey
```

Anders krijgt elke nieuw gebouwde container de oude sleutel mee.

### Commit en push

```bash
git add inventory/group_vars/proxmox/lxcs.yml
git commit -m 'Nieuwe ansible-sleutel'
git push
```

### Test

```bash
ansible all -m ping
```

</Steps>

## Geval 3 — pve01 opnieuw opbouwen

Hopelijk nooit nodig. Doe eerst [geval 1](#geval-1--nieuwe-laptop-klaarzetten).

<Callout type="warning">
De volgorde is geen suggestie. Elke stap heeft iets nodig dat de vorige
achterlaat. Sla er een over en je loopt vast op iets dat er niet uitziet als
het echte probleem.
</Callout>

Wat je nodig hebt buiten deze repo:

- een USB-stick met Proxmox VE
- de **PBS-encryptiesleutel** (staat met opzet niet in git; hoort buiten het huis bewaard, bv. in de wachtwoordkluis)
- op de Mac mini: de gedeelde schijf `/Volumes/media01`

**Deel 1 — pve01 zelf**

<Steps>

### Installeer Proxmox

Van USB, met vast adres **`192.168.0.14`**.

Dat adres staat hard in `inventory/00-static.yml` en in `pve_api_host`. Een
ander adres breekt alles.

### Importeer de ZFS-pool

Als root op `pve01`:

```bash
zpool import vm-hdd      # lukt het niet ("in use by another system"): zpool import -f vm-hdd
```

Overleefde de pool, dan overleefden de VM-schijven én de PBS-datastore. Is hij
weg, dan zijn je back-ups weg — en is dit een heel ander verhaal.

### Maak het API-token

Als root op `pve01`:

```bash
pveum role add AnsibleAutomation --privs "Datastore.AllocateSpace,Datastore.AllocateTemplate,Datastore.Audit,SDN.Use,Sys.Audit,VM.Allocate,VM.Audit,VM.Config.CPU,VM.Config.Disk,VM.Config.Memory,VM.Config.Network,VM.Config.Options,VM.PowerMgmt,VM.GuestAgent.Audit"
pveum user add ansible@pve
pveum acl modify / --user ansible@pve --role AnsibleAutomation
pveum user token add ansible@pve automation --privsep 0   # toont het secret, één keer
```

Kopieer het secret meteen.

<Callout type="info">
Waarom met de hand? De inventory vindt de guests via dit token. Een playbook
heeft het token dus al nodig om te draaien, en kan het niet zelf aanmaken.
</Callout>

### Zet het secret in de twee vault-bestanden

Op je laptop:

```bash
ansible-vault edit inventory/group_vars/proxmox/vault.yml   # vault_pve_api_token_secret
ansible-vault edit inventory/homelab.proxmox.yml            # token_secret
```

<Callout type="warning">
Allebei. `vault.yml` gebruiken de playbooks, `homelab.proxmox.yml` gebruikt de
dynamische inventory. Vergeet je de tweede, dan ziet Ansible geen enkele guest.
</Callout>

### Commit en push

```bash
git add inventory/group_vars/proxmox/vault.yml inventory/homelab.proxmox.yml
git commit -m 'Nieuw Proxmox API-token na herinstallatie pve01'
git push
```

Semaphore draait vanuit git. Zonder push werkt hij straks met het oude token.

### Vertrouw de nieuwe hostkey van pve01

```bash
ssh-keygen -R 192.168.0.14      # vergeet de oude
ssh root@192.168.0.14 exit      # accepteer de nieuwe, typ 'yes'
```

Een herinstallatie geeft `pve01` een nieuwe hostkey. Zonder deze stap weigert
SSH, en met een wachtwoord (`-k`) kan Ansible geen onbekende key accepteren.

### Geef Ansible toegang tot pve01

```bash
ansible-playbook playbooks/bootstrap.yml --limit pve01 -u root -k   # vraagt het root-wachtwoord
```

<Callout type="warning">
`-k` heeft het programma `sshpass` nodig op je laptop. Ontbreekt het, dan
stopt Ansible met een melding daarover.
</Callout>

Een verse Proxmox laat root nog met een wachtwoord binnen. Na de baseline niet
meer: dit is het enige moment waarop `-u root -k` werkt.

### Controleer het token

```bash
ansible-playbook playbooks/proxmox-access.yml
```

Trekt de rechten van het token gelijk en bewijst dat het werkt. Groen = de
inventory kan de guests zien.

</Steps>

**Deel 2 — Back-ups terug in beeld**

PBS is VM 100 en draait op `pve01` zelf. Hij moet dus bestaan vóór je zijn
opslag kunt koppelen.

<Steps>

### Maak vm-hdd bekend in Proxmox

In het Proxmox-scherm: Datacenter → Storage → Add → ZFS.

| Veld | Waarde |
| --- | --- |
| ID | `vm-hdd` |
| ZFS Pool | `vm-hdd` |
| Content | Disk image, Container |

De pool is geïmporteerd, maar Proxmox weet nog niet dat hij hem mag gebruiken.
De PBS-datastore staat op die pool.

### Maak de PBS-VM

Met de hand, exact volgens `vmid: 100` in `inventory/group_vars/proxmox/vms.yml`.

- **MAC-adres overnemen** (`BC:24:11:3D:B4:6A`): daar hangt de DHCP-reservering aan.
- Systeemschijf `scsi0`: nieuw, 32G op `local-lvm`.
- Datastore `scsi1`: **niet nieuw maken**. Koppel de bestaande schijf terug:

```bash
qm rescan --vmid 100     # vindt de oude schijf op vm-hdd als 'unused'
```

Hang die daarna in het scherm aan als `scsi1`, met backup uit.

<Callout type="error">
Een nieuwe 320G-schijf maken voor `scsi1` = een lege datastore. Je back-ups
staan op de oude schijf, nergens anders.
</Callout>

### Installeer PBS in de VM

Van de ISO (`ide2` in `vms.yml`). De oude systeemschijf stond op `local-lvm`
en is met de herinstallatie verdwenen.

Zorg daarna dat de datastore van `scsi1` weer op `/mnt/datastore/store1` hangt.

<Callout type="warning">
Doe dat vóór `pbs.yml` draait. Vindt de rol geen `store1`, dan maakt hij er
een nieuwe, lege aan.
</Callout>

### Breng PBS onder Ansible

```bash
ssh-keygen -R <pbs-adres>
ansible-playbook playbooks/bootstrap.yml --limit pbs -u root -k
ansible-playbook playbooks/pbs.yml
```

De inventory vindt het adres van een VM via de guest-agent (`agent: "1"` in
`vms.yml`). Geen agent in de VM = geen adres = Ansible vindt `pbs` niet.

### Koppel PBS in Proxmox

In het Proxmox-scherm: Datacenter → Storage → Add → Proxmox Backup Server.

- ID: **`pbs`** (de back-upjob en de drills verwachten die naam)
- datastore `store1`, een PBS-gebruiker met wachtwoord
- de **encryptiesleutel** (je bewaarde kopie, zie hierboven)

<Callout type="warning">
Dit staat met opzet niet in een playbook: de definitie draagt de
encryptiesleutel, en die hoort niet in git. Zonder die sleutel zijn je
back-ups onleesbaar.
</Callout>

### Maak de map voor de tweede kopie

Op de **Mac mini**:

```bash
mkdir -p '/Volumes/media01/backups/proxmox'
```

Een NFS-export laat zich niet mounten op een pad dat er niet is. Zonder deze
map komt `macmini-backup` er wel, maar blijft hij inactief.

### Zet de overige opslag en de back-upjobs terug

```bash
ansible-playbook playbooks/proxmox-datacenter.yml -e proxmox_datacenter_create=true
```

Maakt `macmini-backup` en de twee back-upjobs uit
`inventory/group_vars/proxmox/storage.yml` en `backup.yml`.

### Trek pve01 gelijk

```bash
ansible-playbook playbooks/site.yml --limit pve01
```

Pas nu: `site.yml` controleert ook de opslag, en stopt met "Not found on the
node" zolang die er niet is.

</Steps>

**Deel 3 — De machines**

Twee soorten. Guests met **data** zet je terug uit PBS: een nieuwe zou zijn
instellingen of database kwijt zijn. Guests **zonder data** bouw je nieuw.

| Guest | vmid | Hoe |
| --- | --- | --- |
| `adguard` | 107 | terugzetten (eerst: DNS) |
| `semaphore` | 104 | terugzetten |
| `haos` | 101 | terugzetten |
| `docker-grafana-stack` | 102 | terugzetten |
| `docker` | 103 | terugzetten |
| `caddy` | 106 | nieuw bouwen |
| `tailscale` | 108 | nieuw bouwen |

<Steps>

### Zet de guests met data terug uit PBS

Volg [Herstellen, geval 2](/technisch/runbooks/disaster-recovery/#geval-2--terugzetten-uit-de-back-up)
voor elke guest, in de volgorde van de tabel. Kort, op `pve01`:

```bash
sudo pvesm list pbs | grep '/107/'                                    # zoek de nieuwste back-up
sudo pct restore 107 pbs:backup/ct/107/<datum> --storage vm-hdd        # een container
sudo qmrestore pbs:backup/vm/103/<datum> 103 --storage vm-hdd          # een VM
sudo pct start 107                                                     # of: sudo qm start 103
```

- `semaphore` gaat naar `--storage local-lvm`, de rest naar `vm-hdd`.
- `--force` is niet nodig: de guests bestaan nog niet.
- De VM's hoef je niet eerst met de hand te maken. `qmrestore` maakt ze zelf,
  met het MAC-adres uit de back-up.

<Callout type="warning">
Kijk na de restore of onderaan `/etc/pve/lxc/107.conf` de twee `/dev/net/tun`-regels
nog staan (zie de stap voor tailscale hieronder). Ontbreken ze, zet ze erbij en
doe `pct reboot 107`.
</Callout>

### Haal het container-template op

Als root op `pve01`:

```bash
pveam update
pveam download local debian-13-standard_13.1-2_amd64.tar.zst
```

Een verse Proxmox heeft het niet, en de rol haalt het niet zelf op. Het staat
in `pve_lxc_defaults.template` (`lxcs.yml`). Nodig voor de guests die je nieuw bouwt.

### Bouw caddy en tailscale nieuw

```bash
ansible-playbook playbooks/new-guest.yml -e guest=caddy
ansible-playbook playbooks/new-guest.yml -e guest=tailscale
```

Elke run maakt de container, bootstrapt hem en zet de baseline. De dienst zelf
nog niet.

<Callout type="error">
Pas **na** het terugzetten. `new-guest.yml` maakt élke container uit `pve_lxcs`
die nog ontbreekt, ook `adguard` en `semaphore`, maar dan leeg. Staat er dan
al een lege op 107, dan moet je hem eerst weggooien voor de restore.
</Callout>

### Geef tailscale een tun-apparaat

Als root op `pve01`, onderaan `/etc/pve/lxc/108.conf`:

```
lxc.cgroup2.devices.allow: c 10:200 rwm
lxc.mount.entry: /dev/net/tun dev/net/tun none bind,create=file
```

```bash
pct reboot 108     # een mount geldt pas na een start
```

Zonder dit start `tailscaled` niet. Het API-token mag deze regels niet zetten,
dus dit blijft handwerk.

</Steps>

**Deel 4 — Diensten en controle**

<Steps>

### Zet de diensten op de nieuwe containers

```bash
ansible-playbook playbooks/caddy.yml
ansible-playbook playbooks/tailscale.yml
```

### Tailscale: keur de route opnieuw goed

Een opnieuw aangemelde node biedt `192.168.0.0/24` opnieuw aan. Keur die route
goed in de Tailscale admin console, anders werkt toegang van buitenaf niet.

De OAuth-client staat al gevault in `inventory/group_vars/tailnet/vault.yml`.

### Semaphore: trek hem gelijk

```bash
ansible-playbook playbooks/semaphore.yml
```

Niet `site.yml --limit semaphore`: die faalt, want Semaphore moet eerst de
hostkeys van alle machines ophalen.

### Kijk eerst wat er zou veranderen

```bash
ansible-playbook playbooks/site.yml --check --diff
```

En lees het echt. De teruggezette guests draaien de configuratie van de
back-up; je wil zien wat de repo daarvan vindt vóór hij het rechttrekt.

### Trek alles gelijk

```bash
ansible-playbook playbooks/site.yml
```

<Callout type="info">
Stopt `stacks.yml` met een deploy-key? Dat gebeurt alleen op een host die
**nieuw** gebouwd is. Zet de getoonde publieke sleutel in GitHub onder
Settings → Deploy keys (`docker` → `rubenclaes/containers`,
`docker-grafana-stack` → `rubenclaes/monitoring-stack`) en draai opnieuw. Kwam
de host uit PBS, dan staat de oude sleutel er nog.
</Callout>

### Werk de docs en het rapport bij

```bash
ansible-playbook playbooks/docs.yml
ansible-playbook playbooks/report.yml
```

</Steps>

## Goed om te weten

### Waarom twee vault-wachtwoorden

Een keuze over schade bij een lek:

| Identiteit | Beschermt | Een lek betekent |
| --- | --- | --- |
| `infra` | inventory-vaults, `homelab.proxmox.yml`, Semaphore-config | controle over hypervisor, DNS en back-ups roteren |
| `stacks` | `files/env/*.env` | applicatie-logins roteren |

### Waarom de pre-commit hook

Een gecommit geheim blijft in de git-historie staan, ook als je het bestand
daarna weggooit. CI vangt het pas na de push, en dan staat het al op GitHub.
De hook is de poort, CI het vangnet.

### `bootstrap.yml` doet één host tegelijk

Hij weigert meer dan één host. Zonder die grendel herschrijft een vergeten
`--limit` `/etc/sudoers.d/ansible` op alle hosts. Er gaat niets stuk, maar een
playbook voor één nieuwe machine hoort de rest niet te raken.

### Waarom `proxmox-access.yml` via het token test

Hij vraagt de guest-agent op dóór het token heen, niet met `pvesh`. `pvesh`
draait als root en slaagt altijd, dus dat bewijst niets over wat de
inventory straks ziet.

### `new-guest.yml` maakt meer dan je vraagt

De container-rol maakt élke container uit `pve_lxcs` die nog ontbreekt, niet
alleen de genoemde. Bootstrappen en baselinen doet hij wel alleen op de
genoemde. Daarom zet je bij een herbouw eerst terug uit PBS en bouw je pas daarna nieuw:
anders staan er lege containers op de nummers die je wilde terugzetten.

### Niet alles komt uit een playbook terug

`macmini` en `docker-grafana-stack` draaien diensten die deze repo nog niet
kan terugbouwen: daar is PBS het herstelpad. Wat ze draaien zie je met
`discover.yml`, zie [Onderhoud](/technisch/runbooks/onderhoud/). Ook de
AdGuard-instellingen (`AdGuardHome.yaml`) en de database van Semaphore zet geen
rol terug. Daarom komen die twee uit PBS en niet uit `new-guest.yml`.
