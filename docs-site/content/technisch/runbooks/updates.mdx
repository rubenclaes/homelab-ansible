# Updates

`playbooks/update.yml` draait `apt full-upgrade` met `serial: 1`: één host is
helemaal klaar voordat de volgende begint. Een mislukte upgrade sloopt één
machine, niet de vloot.

Het playbook bestaat uit **twee plays**, en die volgorde is het punt. Eerst alle
guests, daarna pas de hypervisor. In één play zou `pve01` kunnen herstarten
terwijl de guests die erop draaien nog bezig zijn — en die gaan dan mee.

## Reboots zijn opt-in

Standaard meldt het playbook alleen dát een reboot nodig is. Twee losse
schakelaars, allebei uit:

| Variabele | Doet |
|---|---|
| `allow_reboot` | herstart guests die het nodig hebben |
| `allow_hypervisor_reboot` | staat daarbovenop toe dat ook `pve01` herstart |

```bash
# De wekelijkse ronde. Semaphore draait dit zondag om 04:00.
ansible-playbook playbooks/update.yml --limit guests

# Met reboots waar nodig, guests alleen.
ansible-playbook playbooks/update.yml -e allow_reboot=true

# Inclusief de hypervisor. Beide vlaggen nodig; dit legt elke guest plat.
ansible-playbook playbooks/update.yml \
  -e allow_reboot=true -e allow_hypervisor_reboot=true
```

`allow_hypervisor_reboot` op zichzelf doet niets — `allow_reboot` moet er ook
staan. Zo kan een gewone run nooit per ongeluk de hypervisor meenemen.

<Callout type="error">
Draai de `pve01`-upgrade nooit vanuit Semaphore. Semaphore is een container
**op** `pve01`, dus een reboot doodt de job die hem gaf. Een controller
herstart de machine waar hij zelf op draait niet.
</Callout>

## Caddy staat vast

`caddy` is gepind via `baseline_held_packages`, want het is een custom build met
de plugin `caddy-dns/cloudflare`. Een gewone `apt full-upgrade` verving hem ooit
door het standaardbinary, dat weigert te starten tegen een Caddyfile met de
Cloudflare DNS-module — waarmee elke `*.neodata.be`-naam onderuit ging.

`dist-upgrade` respecteert dpkg-holds, dus een update-run raakt hem niet aan.
Upgraden doe je bewust, en dat behoudt de plugins:

```bash
ansible caddy -a "caddy upgrade"
```

Daarna `playbooks/caddy.yml` en `playbooks/caddy-smoketest.yml` om te
controleren dat er niets stuk is.
