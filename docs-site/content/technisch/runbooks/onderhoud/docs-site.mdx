# De docs-site bijwerken

Je veranderde iets in de inventory of de runbooks. `playbooks/docs.yml` maakt
de pagina's onder Technisch opnieuw, bouwt de site en zet hem op `caddy`.

<Steps>

### Commit en push je wijziging eerst

```bash
git add inventory docs-site && git commit -m '...' && git push
```

<Callout type="warning">
Semaphore bouwt de site elke dag om 07:00 opnieuw, **uit git**. Wat je alleen
lokaal hebt, staat de volgende ochtend weer niet online.
</Callout>

### Bouw en publiceer

```bash
ansible-playbook playbooks/docs.yml
```

Verzamelt eerst facts van `linux:macs`, genereert de pagina's, en draait dan
`npm ci` en `npm run build` op je eigen machine; alleen het resultaat gaat naar
de `caddy`-host.

### Kijk na

Open [docs.neodata.be](https://docs.neodata.be). Werkt alleen vanaf het LAN of
de tailnet.

</Steps>

## Wat waar vandaan komt

| Deel | Bron |
| --- | --- |
| **Technisch → [Machines](/technisch/machines/)**: elke machine met adres, diensten en stacks | gegenereerd uit de inventory door `docs.yml` |
| **Technisch → [Diensten](/technisch/services/)**: één pagina per route in `caddy_sites`, plus diensten zonder route uit `docker_services_without_route` | gegenereerd uit de inventory door `docs.yml` |
| **Runbooks** (zoals deze pagina) | met de hand geschreven, alleen meegenomen |

Bewerk dus nooit een pagina onder Machines of Diensten: de volgende run
overschrijft hem. Een geschrapte route laat geen pagina achter: die wordt
vanzelf opgeruimd, pas nadat de rest opnieuw gerenderd is.

<Callout type="info">
Draai dit na **elke** wijziging in de inventory. Een site die iets beweert wat
niet meer waar is, is erger dan geen documentatie: je gelooft hem.
</Callout>

<Callout type="warning">
Faalt hij op "De inventory is incompleet"? Dan laadde `homelab.proxmox.yml`
niet (API plat, token verlopen). Controleer met `ansible-inventory --graph`;
er is dan niets geschreven. Zie [Guests en API-token](/technisch/runbooks/onderhoud/guests/).
</Callout>
