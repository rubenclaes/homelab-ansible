# Onderhoud

Gebruik deze pagina als je wil **kijken, opruimen of opschrijven**, niet
installeren. Onderaan staat wat er vanzelf draait, zonder dat jij iets typt.

Alle commando's draai je vanuit de root van deze repo.

## Welk geval ben jij?

| Jouw situatie | Voorbeeld | Ga naar |
| --- | --- | --- |
| Je wil in één oogopslag zien of alles gezond is | openstaande updates, certificaat bijna verlopen, een poort zonder route | [Geval 1 — Gezondheidsrapport](#geval-1--gezondheidsrapport) |
| Je vermoedt dat er iets met de hand gewijzigd is | iemand paste een config aan op `caddy` buiten de repo om | [Geval 2 — Drift zoeken](#geval-2--drift-zoeken) |
| Je wil weten of DNS nog klopt | `ssh pve01.home.arpa` vindt de host niet meer | [Geval 3 — DNS controleren](#antwoordt-dns-nog-wat-het-moet) |
| Een schijf loopt vol | oude kernels op `pve01`, oude images op `docker` | [Geval 4 — Schijfruimte vrijmaken](#geval-4--schijfruimte-vrijmaken) |
| Je weet niet precies wat er op een host draait | `docker-grafana-stack`, de Mac mini | [Geval 5 — Een host in kaart brengen](#geval-5--een-host-in-kaart-brengen) |
| Je wil weten welke guests er echt draaien, of het API-token nog werkt | Ansible ziet een host niet | [Geval 6 — Guests en API-token checken](#geval-6--guests-en-api-token-checken) |
| Je wil zien wie er aanklopte bij de reverse proxy | 500-fouten op `plex.neodata.be` | [Geval 7 — Caddy-logs doorzoeken](#geval-7--caddy-logs-doorzoeken) |
| Je veranderde iets in de inventory of de runbooks | nieuwe route, andere hostnaam | [Geval 8 — De docs-site bijwerken](#geval-8--de-docs-site-bijwerken) |
| Je wil een schema in Semaphore toevoegen of wijzigen | Drift check een uur later laten lopen | [Geval 9 — Een schema in Semaphore aanpassen](#geval-9--een-schema-in-semaphore-aanpassen) |

Wil je alleen weten **wat er vanzelf draait en wanneer**? Zie
[Wat draait er vanzelf?](#wat-draait-er-vanzelf)

### Woorden die je nodig hebt

**Drift** — een host die niet meer overeenkomt met wat de repo beschrijft.

**Converge** — `site.yml` draaien, zodat elke host weer gelijk is aan de repo.

**Template** — een job in Semaphore: een playbook, argumenten en eventueel een schema (cron).

**Demper** — een regel in de host_vars die een melding in het rapport bewust stilzet, mét reden.

## Geval 1 — Gezondheidsrapport

<Steps>

### Draai het rapport

```bash
ansible-playbook playbooks/report.yml   # leest alleen, verandert niets
```

Draai hem **zonder** `--limit`, of neem `localhost` erin mee
(`--limit docker:localhost`). De HTML wordt op `localhost` gemaakt.

### Open het rapport

Ga naar [report.neodata.be](https://report.neodata.be). Werkt alleen vanaf het
LAN of de tailnet.

Per host: openstaande updates, herstart nodig, schijfgebruik. Daarnaast de
PBS-back-ups, de vervaldatum van het wildcard-certificaat en de vergelijkingen
hieronder.

### Lees de vergelijkingen

| Vergelijking | Staat hier iets, dan betekent het |
| --- | --- |
| route → draaiende container | een naam die nergens heen wijst; tijdens een storing kost hij je tien minuten |
| container → route | een dienst die je niet hebt afgemaakt, alleen bereikbaar als `host:poort` |
| draaiend project → `docker_stacks_list` | draait wel, maar niets kan hem terugzetten |
| `wait_for_mounts` → `nfs_mounts` | een herbouwde host blijft bij het opstarten hangen op een mount die nooit komt |
| back-upgroep → bestaande guest | een back-up van een guest die niet meer bestaat; kost ruimte |

Een poort zonder route is meestal een dienst die je vergeten bent af te maken:
volg dan [Dienst toevoegen](/technisch/runbooks/dienst-toevoegen/).

### Demp wat bewust zo is

Is een melding gewild? Zet ze in de host_vars van die host, bijvoorbeeld
`inventory/host_vars/docker.yml`:

```yaml
docker_ports_without_route:
  - { port: 21115, why: "rustdesk hbbs - raw TCP, not HTTP" }

docker_routes_without_container:
  - { port: 8089, why: "qbittorrent draait met host-netwerk, geen poortmapping" }
```

| Var | Voor |
| --- | --- |
| `docker_ports_without_route` | een gepubliceerde poort die bewust geen route heeft |
| `docker_routes_without_container` | een route waarvan de backend géén containerpoort is (qbittorrent met `network_mode: host`, Plex als macOS-app) |

<Callout type="warning">
Zet er **altijd** een `why:` bij. Een gedempte melding zonder reden is over
een half jaar niet te onderscheiden van een vergissing.
</Callout>

### Commit en push

```bash
git add inventory && git commit -m 'Rapport: poort 21115 gedempt' && git push
```

</Steps>

## Geval 2 — Drift zoeken

<Steps>

### Draai de driftcheck

```bash
ansible-playbook playbooks/drift.yml                     # samenvatting
ansible-playbook playbooks/drift.yml -e drift_fail=true  # rood bij drift
```

Draait `site.yml --check --diff` en geeft één regel per host, plus de namen van
de taken die iets zouden wijzigen. Verandert zelf niets.

### Controleer of elke host bereikt is

Staat er `NIET BEREIKT` in plaats van `gelijk aan de repo`? Dan is er op die
host **niets gecontroleerd**.

<Callout type="error">
Een host die niet bereikbaar is telt als nul wijzigingen. Een slapende Mac ziet
er in het totaal uit als een host zonder drift. Lees dus de regel per host.
</Callout>

### Lees de echte diffs

```bash
less .drift/site-check.log
```

De samenvatting zegt wie en wat. Hoe precies, staat in dit log (gitignored).

### Kies wie gelijk heeft

- **De repo klopt** → trek de host gelijk:
  `ansible-playbook playbooks/site.yml --limit <host>`
- **De host klopt** → zet de wijziging in de repo (inventory of rol), commit
  en push, en draai `drift.yml` opnieuw.

</Steps>

## Geval 3 — DNS controleren [#antwoordt-dns-nog-wat-het-moet]

<Steps>

### Draai de DNS-test

```bash
ansible-playbook playbooks/dns-smoketest.yml
```

Vraagt `<host>.home.arpa` op voor elke host met een adres, rechtstreeks bij
AdGuard (`192.168.0.29`), en vergelijkt met het adres in de inventory. Daarna
nog één publieke naam (`google.com`).

### Lees wat rood is

Je krijgt de naam en beide adressen te zien.

| Rood op | Betekent |
| --- | --- |
| een `.home.arpa`-naam | een rewrite ontbreekt of wijst naar een **oud adres** |
| de publieke naam | AdGuards upstream is weg: het huis vindt geen enkele naam meer |

Een andere publieke naam kies je met `-e dns_smoketest_public_name=...`.

### Zet de rewrites opnieuw en test

```bash
ansible-playbook playbooks/adguard.yml
ansible-playbook playbooks/dns-smoketest.yml
```

Meer over DNS: [Netwerk](/technisch/runbooks/netwerk/).

</Steps>

<Callout type="info">
Draait ook vanzelf, dagelijks om 06:30. Het vult `caddy-smoketest.yml` aan en
vervangt hem niet: Caddy praat met adressen, dus een kapotte rewrite laat de
`neodata.be`-routes gewoon werken terwijl `ssh pve01.home.arpa` stil stuk is.
</Callout>

## Geval 4 — Schijfruimte vrijmaken

<Steps>

### Kijk eerst wat er weg kan

```bash
ansible-playbook playbooks/cleanup.yml                 # rapporteert alleen
ansible-playbook playbooks/cleanup.yml --limit macs    # alleen de Macs (brew-cache)
```

Zonder vlag verandert hij niets. Je krijgt de **namen** van wat weg zou gaan,
niet alleen een aantal.

### Lees het lijstje

Let vooral op `pve01`: daar duiken oude `proxmox-kernel-*`-pakketten op. Dat
lijstje zien vóór je opruimt, is het hele punt van deze stap.

### Ruim echt op

```bash
ansible-playbook playbooks/cleanup.yml -e cleanup_apply=true
```

<Callout type="warning">
Zet `cleanup_apply` **nooit** in de inventory. Het is de schakelaar die een
rapport in een verwijdering verandert; een default in `group_vars` maakt elke
run destructief.
</Callout>

</Steps>

Wat hij **nooit** aanraakt:

| Blijft staan | Waarom |
| --- | --- |
| Docker-volumes | daar staat de data van de stacks; weggooien is een restore, geen cleanup |
| containers, ook gestopte | een gestopte container houdt zijn image buiten de prune, dus een `down`-stack overleeft dit |
| gepinde pakketten | `autoremove` respecteert dpkg-holds, dus de custom Caddy-build blijft |
| de geïnstalleerde Homebrew-versie | alleen oude versies en oude downloads gaan |

De knoppen staan in `inventory/group_vars/all/cleanup.yml`:

| Var | Standaard | Doet |
| --- | --- | --- |
| `cleanup_journal_keep` | `14d` | hoeveel journal-geschiedenis blijft |
| `cleanup_docker_until` | `720h` | ongebruikte images jonger dan dit blijven staan |
| `cleanup_brew_prune` | `30` | brew-downloads ouder dan zoveel dagen gaan weg |

<Callout type="info">
Pakketten weghalen die je niet meer wil, doe je **niet** hier: dat gaat via de
`*_absent`-lijsten in de host_vars en `site.yml`. Zie
[Updates](/technisch/runbooks/updates/) voor het verschil.
</Callout>

## Geval 5 — Een host in kaart brengen

<Steps>

### Lees de host uit

```bash
ansible-playbook playbooks/discover.yml --limit docker-grafana-stack
```

Leest compose-projecten, containers en poorten (Docker-hosts) of
`brew leaves` en casks (Macs). Verandert niets.

### Lees het voorstel

```bash
$EDITOR .discovered/docker-grafana-stack.yml
```

Dit is **geen inventory**, het is een voorstel. Gooi eruit wat er niet in hoort.

### Zet de rest in de host_vars

```bash
$EDITOR inventory/host_vars/docker-grafana-stack.yml
```

Zodra een host een `docker_stacks_list` heeft, pakt `stacks.yml` hem vanzelf
op. Dat ene veld maakt een host beheerd.

### Probeer droog

```bash
ansible-playbook playbooks/stacks.yml --limit docker-grafana-stack --check --diff
```

### Commit en push

```bash
git add inventory && git commit -m 'docker-grafana-stack beschreven' && git push
```

</Steps>

## Geval 7 — Caddy-logs doorzoeken

Elk verzoek van buiten gaat langs `caddy`. Grafana Alloy stuurt die logs naar
Loki in de monitoring-stack.

<Steps>

### Open Grafana

Ga naar [monitoring.neodata.be](https://monitoring.neodata.be) en zoek in Loki.

### Kies wat je wil zien

| Query | Wat je ziet |
| --- | --- |
| `{job="caddy"}` | elk verzoek dat de reverse proxy afhandelde |
| `{job="caddy-runtime"}` | wat Caddy zelf meldt: certificaten, herladen, fouten |

### Filter met `| json`

```
{job="caddy"} | json | status >= 500
{job="caddy"} | json | request_host = "plex.neodata.be"
```

</Steps>

Wil je **andere logbestanden** versturen:

<Steps>

### Pas de lijst aan

```bash
$EDITOR inventory/host_vars/caddy/main.yml   # alloy_log_targets
```

Welke hosts een agent krijgen, staat in de groep `alloy_hosts` in
`inventory/00-static.yml`. Nu is dat alleen `caddy`.

### Zet het live

```bash
ansible-playbook playbooks/alloy.yml
```

### Commit en push

```bash
git add inventory && git commit -m 'Alloy: extra logbestand' && git push
```

</Steps>

<Callout type="warning">
Zet de Docker-hosts **niet** in `alloy_hosts`. De Alloy ín de monitoring-stack
haalt hun containerlogs al via de Docker-socket; een tweede agent stuurt alles
dubbel.
</Callout>

```bash

```

<Callout type="warning">


### Kijk na

Open [docs.neodata.be](https://docs.neodata.be). Werkt alleen vanaf het LAN of
de tailnet.

</Steps>

Wat waar vandaan komt:

| Deel | Bron |
| --- | --- |
| **Technisch**: hosts, LXC's, stacks, één pagina per route | gegenereerd uit de inventory |
| **Runbooks** (zoals deze pagina) | met de hand geschreven, alleen meegenomen |

Een geschrapte route laat geen pagina achter: die wordt bij de volgende run
vanzelf opgeruimd.

<Callout type="info">
Draai dit na **elke** wijziging in de inventory. Een site die iets beweert wat
niet meer waar is, is erger dan geen documentatie: je gelooft hem.
</Callout>

## Geval 9 — Een schema in Semaphore aanpassen

De templates en hun schema's staan in `semaphore_templates_list` in
`inventory/host_vars/semaphore/main.yml`. Het playbook zet ze via de API in
Semaphore.

<Steps>

### Kijk eerst wat er in de UI staat

Open Semaphore en noteer de **exacte** naam van de template, met hoofdletters.

<Callout type="error">
`name` is de sleutel waarop gezocht wordt. `Cleanup (apply)` is niet
`Cleanup (Apply)`: een andere schrijfwijze maakt een **tweede** template in
plaats van de bestaande te wijzigen. Zo stonden er op 23-09 drie dubbele jobs,
waaronder een site-converge zonder zijn limit.
</Callout>

### Pas de lijst aan

```bash
$EDITOR inventory/host_vars/semaphore/main.yml
```

```yaml
- name: "Drift check"
  playbook: playbooks/drift.yml
  description: "Wat zou site.yml veranderen? Faalt als het antwoord niet 'niets' is."
  arguments: ["-e", "drift_fail=true", "-e", "drift_limit=all:!mbp:!semaphore"]
  schedule: "0 6 * * *"   # lokale tijd (Europe/Brussels)
```

Laat de limits staan. Waarom: zie
[De limits in de templates](#de-limits-in-de-templates).

### Probeer droog

```bash
ansible-playbook playbooks/semaphore-templates.yml --check
```

Lees de rapportageregel. Staat een template die je wilde **wijzigen** onder
`create`? Dan wijkt de naam af. Stop en verbeter de naam.

### Zet het echt

```bash
ansible-playbook playbooks/semaphore-templates.yml
```

### Commit en push

```bash
git add inventory && git commit -m 'Semaphore: schema Drift check' && git push
```

</Steps>

<Callout type="info">
Eerste keer op een nieuwe controller? De API-login staat in
`inventory/host_vars/semaphore/vault.yml` (`vault_semaphore_api_user`,
`vault_semaphore_api_password`). Ontbreekt dat bestand, dan faalt de rol met
een melding. Hoe je het aanmaakt, staat bovenaan `main.yml` in die map.
</Callout>

Wat de rol **wel** en **niet** doet:

| Doet | Doet niet |
| --- | --- |
| templates aanmaken en bijwerken | templates verwijderen: wat je uit de lijst haalt, blijft in de UI staan, mét schema |
| de cron zetten | een gepauzeerd schema weer aanzetten |
| naam, playbook, argumenten, beschrijving | surveys, views, vaults en de vlaggen onder *Advanced* |

`site.yml` draait `semaphore-templates.yml` ook mee, maar alleen als je hem
**met de hand en zonder limit** draait. De geplande `Site converge` slaat hem
over; zie [Een schema herschrijft zichzelf niet](#een-schema-herschrijft-zichzelf-niet).

## Wat draait er vanzelf?

### In Semaphore, met schema

Tijden zijn lokale tijd (Europe/Brussels).

| Template | Wanneer | Waarom dan |
| --- | --- | --- |
| Cleanup (Apply) | zaterdag 03:00 | zonder deze ruimt de rapportageversie nooit iets op |
| Update guests | zondag 04:00 | een uur vóór de converge, zodat die de nasleep opruimt |
| Site converge | zondag 05:00 | wekelijks gelijktrekken; drift repareert zichzelf |
| Stacks | dagelijks 05:30 | ná de converge van zondag, vóór Drift check |
| Drift check | dagelijks 06:00 | je ziet wat er tussen twee converges afwijkt |
| DNS smoketest | dagelijks 06:30 | tussen Drift check en Docs; twee jobs op dezelfde minuut vechten om dezelfde controller |
| Docs | dagelijks 07:00 | de site volgt de repo |
| Homelab Report | zondag 08:00 | traag, dus wekelijks |
| Restore drill | 1e van de maand, 04:00 | maakt en sloopt een echte guest; niet elke nacht |

### In Semaphore, zonder schema (klik ze zelf)

| Template | Doet |
| --- | --- |
| Baseline (dry run) | `baseline.yml --check --diff`: droogloop, verandert niets |
| Caddy | `caddy.yml` |
| Cleanup (report) | rapporteert wat er vrij kan, verwijdert niets |

Daarmee staan alle twaalf templates van het project in git. Maak je er een in
de UI, zet hem dan ook in `semaphore_templates_list`, anders is dat bestand
weer een deellijst en geloof je hem ten onrechte.

### Op pve01, niet in Semaphore

De back-ups draaien op de cron van Proxmox. Ze staan in `pve_backup_jobs` in
`inventory/group_vars/proxmox/backup.yml`.

| Job | Wanneer | Waarheen | Waarom |
| --- | --- | --- | --- |
| dagelijks | 02:30 | PBS, op pve01 | de primaire: incrementeel, 7 snapshots, versleuteld |
| wekelijks | zondag 01:00 | de Mac mini, over NFS | tweede kopie, voor als pve01 zelf weg is |

Terugzetten: [Herstellen](/technisch/runbooks/disaster-recovery/#geval-7--terugvallen-op-de-tweede-kopie).

<Callout type="warning">
**Niets hiervan meldt zichzelf als het faalt**, niet in Semaphore en niet op
Proxmox. De wekelijkse back-up schrijft naar een Mac die kan slapen. Tot er
meldingen zijn, is elk schema een aanname: kijk af en toe zelf in de
taaklijst. Staat bovenaan `TODO.md`.
</Callout>

## Goed om te weten

### Waarom deze playbooks niet in `site.yml` zitten

`site.yml` trekt gelijk. `report.yml` is traag en hoort op een schema,
`drift.yml` en `dns-smoketest.yml` controleren alleen, en `cleanup.yml`
verwijdert. Uitzondering: `semaphore-templates.yml` zit er wél in, sinds 23-09.

### De limits in de templates

- **`!semaphore`** — houdt een job van zijn eigen container af. Herstart
  Semaphore halverwege, dan is de job dood en weet je niet of hij af is. Die
  machine patch je met de hand.
- **`!mbp`** — `mbp` heeft `ansible_connection: local`. Vanuit Semaphore
  betekent dat "de container die de job draait", niet je MacBook. Die zit in
  `macs` en krijgt dan macOS-taken: zo liep `Cleanup (report)` op 23-09 vast
  op "Measure the Homebrew cache" in een Debian-container. Aan je bureau klopt
  `mbp` wel; daar draai je zonder limit.
- **`localhost`** bij `Homelab Report` (`all:!mbp:localhost`) — `all` telt de
  impliciete `localhost` niet mee. Zonder hem is de run groen maar verschijnt
  er niets op report.neodata.be. Een limit die te veel wegsnijdt maakt een job
  niet rood, alleen stil.
- **`drift_limit`** in plaats van `--limit` bij `Drift check` — `drift.yml`
  draait zelf op `localhost`; een `--limit` zou die play raken, niet de
  droogloop eronder.

### Een schema herschrijft zichzelf niet

`Site converge` draait met `--limit all:!mbp:!semaphore`, dus de play
`semaphore-templates.yml` in `site.yml` valt daar weg. Dat is met opzet: een
schema dat zijn eigen schema's herschrijft terwijl het draait, wil je niet.

### Waarom de tijden lokale tijd zijn

Tot 23-09 las Semaphore elke cron als UTC (`Drift check` met `0 6 * * *`
eindigde op `06:00:37Z`, dus 08:00 hier). UTC schuift mee met de zomertijd.
De `semaphore`-rol zet nu `SEMAPHORE_SCHEDULE_TIMEZONE` uit
`semaphore_schedule_timezone` (`Europe/Brussels`), als omgevingsvariabele en
niet in de gevaulte `config.json`, zodat je hem kunt nalezen.

### Baseline (dry run) deed vroeger echt iets

Tot 23-09 draaide hij `baseline.yml` **zonder** `--check`: wie ging kijken,
paste de baseline toe op elke Linux-host. Nu met `--check --diff`. Niet
hernoemd, want een nieuwe naam maakt een tweede template en laat de
geschiedenis achter.

### Waarom `Stacks` dagelijks draait

Na een herstart van OrbStack komen `duplicati` en `shelfmark` op de Mac mini
niet terug: ze koppelen een schijf onder `/Volumes` aan die OrbStack pas later
doorgeeft, en `restart: unless-stopped` helpt niet tegen een start die mislukt.
Een dagelijkse run herstelt dat binnen een dag. De eerste beheerde run is op
23-09 met de hand gedaan en was schoon (`changed=0`): een schema dat zijn
eerste run onbewaakt doet, is een gok.

### De Semaphore-API kent geen gedeeltelijke update

Een `UPDATE` zet élke kolom uit het verzoek; wat je weglaat wordt leeg. Daarom
bouwt de rol het verzoek op uit wat de server nu heeft, met alleen onze velden
erover. Om dezelfde reden stuurt hij `environment_ids` mee: laat je dat weg,
dan draait de template zonder environment. Denk hieraan voor je de rol
"vereenvoudigt".

### Waarom `brew cleanup` niet in `update.yml` zit

Op de MacBook komt `ansible` zelf uit Homebrew en is de verbinding `local`. Een
update vervangt de interpreter die de playbook draait; `brew cleanup` zou daarna
de map weggooien waar dat proces nog uit leest. Daarom zet `update.yml`
`HOMEBREW_NO_INSTALL_CLEANUP=1`, en zit de opruiming in `cleanup.yml`, dat
niets upgradet.

### Images en build cache

Images hebben een leeftijdsgrens (`cleanup_docker_until`), build cache niet. Een
image dat toch nodig blijkt moet opnieuw over het netwerk; build cache wordt
gewoon opnieuw gebouwd.

### De DNS-test rekent zelf

`dns-smoketest.yml` berekent de lijst namen op dezelfde manier als de
`adguard`-rol, maar met een eigen kopie van die uitdrukking. Leende hij de lijst
van de rol, dan zou een fout in die lijst zichzelf goedkeuren.

### De rapportvergelijkingen lopen over alle containerhosts

`docker`, `docker-grafana-stack` en de Mac mini (`docker_hosts` plus `macs`,
dezelfde regel als `stacks.yml`). Tot 22-09 keek hij alleen naar `docker`, en

### Alloy en de rechten op de logbestanden

Alloy draait als gebruiker `alloy`, niet als root, en leest via groep `caddy`.
Daarom staat `caddy_log_mode` op `0640`. Caddy past die mode toe bij het
**openen** van een bestand: na `systemctl reload caddy` bleef het `0600`, pas
na `systemctl restart caddy` (of de rotatie om middernacht) werd het `0640`.
De regels zijn JSON en krijgen geen label per statuscode of pad, omdat Loki op
labels indexeert: pel af bij het zoeken, niet bij het schrijven.

### docs en report zijn niet publiek

`docs.neodata.be` en `report.neodata.be` staan niet in `caddy_sites` maar als
vaste blokken in de Caddyfile. Ze serveren van schijf en geven een 403 buiten
het LAN en de tailnet: ze beschrijven de binnenkant van het netwerk.
