# Disaster recovery

Een verloren guest terugbouwen is vier playbooks. De data komt van Proxmox
Backup Server, de rest staat in Git.

<Steps>

### Container opnieuw aanmaken

```bash
ansible-playbook playbooks/proxmox-lxcs.yml
```

De rol vergelijkt `pve_lxcs` met wat Proxmox werkelijk heeft en maakt alleen aan
wat ontbreekt. Bestaande containers worden nooit aangepast, dus dit mag altijd
draaien.

Het adres van een container staat letterlijk in `pve_lxcs` en wordt daar niet
afgeleid uit de inventory: een container die nog niet bestaat, staat ook niet in
de Proxmox-inventory. Dit bestand is de bron van het adres tot Proxmox de
container kent — daarna neemt de inventory het over.

### Serviceaccount aanmaken

```bash
ansible-playbook playbooks/bootstrap.yml --limit <host> \
  -e ansible_user=root -e ansible_become=false
```

Een net aangemaakte container draagt de Ansible-publieke sleutel al, dus dit is
de enige stap die als root praat. Een host die de sleutel níét heeft (geen
Proxmox-guest, bijvoorbeeld) gaat met `-u root -k` en een wachtwoord.

### Baseline toepassen

```bash
ansible-playbook playbooks/baseline.yml --limit <host>
```

Dit zet ook `qemu-guest-agent` op VM's. Zonder die agent meldt een VM geen adres
en valt hij uit de dynamische inventory.

### Servicerol toepassen

`playbooks/caddy.yml`, `playbooks/semaphore.yml`, `playbooks/stacks.yml` — welke
de host ook is.

</Steps>

<Callout type="warning">
Een herbouwde host heeft een **nieuwe SSH-hostkey**. Je werkstation weigert te
verbinden tot je `ssh-keygen -R <adres>` draait. Semaphore repareert zichzelf bij
de volgende run van `playbooks/semaphore.yml`, die hostkeys uit facts verzamelt.
</Callout>

## De hele node kwijt

Na het herinstalleren van Proxmox zelf heeft het API-token nog geen rechten. De
dynamische inventory is dan leeg, want die haalt guests via dat token op:

```bash
ansible-playbook playbooks/proxmox-access.yml
```

Die zet de rechten van de rol `AnsibleAutomation` terug, inclusief
`VM.GuestAgent.Audit` — zonder dat geeft het guest-agent-endpoint 403 en krijgen
de QEMU-guests geen adres.

## Testen

Het herstelpad is pas echt als het gedraaid heeft. Zet een wegwerp-entry in
`pve_lxcs`, laat de rol hem bouwen, gooi hem weg met `pct destroy` en draai de
rol opnieuw.

Controleer daarna dat de inventory klopt:

```bash
ansible-inventory --graph
ansible all -m ping
```
