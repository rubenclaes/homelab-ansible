# Laptop klaarzetten

Eén keer doen op een nieuwe laptop. Daarna werken `ssh caddy`, `ap` en elk
playbook. Alleen `~/.zshrc` of `~/.ssh/config` kwijt? Begin bij stap 6.

## Wat je nodig hebt

| Wat | Waar vind je het |
| --- | --- |
| de `ansible`-sleutel (`~/.ssh/ansible_ed25519`) | je oude Mac, of de wachtwoordkluis |
| de twee vault-wachtwoorden (`infra`, `stacks`) | de wachtwoordkluis |
| je eigen sleutel `~/.ssh/id_ed25519` | je oude Mac (git signeert er elke commit mee) |

## De stappen

<Steps>

#### 1. Haal de repo binnen

```bash
git clone https://github.com/rubenclaes/homelab-ansible.git ~/Development/homelab-ansible
cd ~/Development/homelab-ansible
```

#### 2. Installeer Ansible

```bash
brew install ansible ansible-lint
ansible-galaxy collection install -r collections/requirements.yml
```

**Let op:** Zonder `proxmoxer` (zit in de brew-versie) ziet Ansible alleen `pve01` en de
Macs, zonder foutmelding. Met pipx: `pipx inject ansible-core proxmoxer requests`.

#### 3. Zet de ansible-sleutel neer

```bash
scp <oude-mac>:'~/.ssh/ansible_ed25519*' ~/.ssh/
chmod 600 ~/.ssh/ansible_ed25519
```

<Callout type="error">
Maak deze sleutel **nooit** opnieuw aan: elke host kent de bestaande. Echt
kwijt? Zie [De ansible-sleutel is kwijt](/ansible/sleutel/#de-ansible-sleutel-is-kwijt).
</Callout>

#### 4. Zet de vault-wachtwoorden neer

```bash
mkdir -p ~/.ansible
install -m 600 /dev/null ~/.ansible/vault_pass_infra
install -m 600 /dev/null ~/.ansible/vault_pass_stacks
$EDITOR ~/.ansible/vault_pass_infra     # plak het infra-wachtwoord
$EDITOR ~/.ansible/vault_pass_stacks    # plak het stacks-wachtwoord
```

Geen spatie of lege regel erachter, anders klopt het wachtwoord niet.

#### 5. Zet de pre-commit hook aan en test

```bash
git config core.hooksPath .githooks   # blokkeert een commit met een geheim erin
bin/check-vaulted && ansible-lint && ansible all -m ping
```

#### 6. Schrijf je ssh-config en shell

```bash
ansible-playbook playbooks/dotfiles.yml
exec zsh
ssh caddy     # moet binnenkomen zonder wachtwoord
```

Zegt hij "`~/.ssh/config.d/homelab` niet aangeraakt"? Dan was de Proxmox-API
niet bereikbaar. Kijk met `ansible-inventory --graph` en draai opnieuw.

</Steps>

Niets te committen: dit staat allemaal alleen op je laptop.

**Extra, alleen als je het nodig hebt:** Node.js om `docs.yml` te draaien, en
de `containers`-repo in `~/Development/containers` om diensten toe te voegen.

## Een nieuwe machine bij naam

Nieuwe machine gemaakt en `ssh <naam>` werkt nog niet? Draai opnieuw:

```bash
ansible-playbook playbooks/dotfiles.yml
```

De nachtelijke run in Semaphore doet je laptop níét, dus dit doe je zelf.
Staat de machine er dan nog niet in? Kijk met `ansible-inventory --graph linux`.

## Goed om te weten

### Wat `dotfiles.yml` schrijft

| Bestand | Wat erin staat |
| --- | --- |
| `~/.ssh/config.d/homelab` | een blok per Linux-machine, uit de inventory |
| `~/.ssh/config` | één regel `Include ~/.ssh/config.d/*`, bovenaan |
| `~/.zshrc` | je shell met de afkortingen |
| `~/.gitconfig` | naam, e-mail, commits signeren |

Bewerk die bestanden niet met de hand: de volgende run overschrijft ze. Pas de
inventory aan, zie [Handige commando's](/ansible/commandos/#een-afkorting-toevoegen).

Staat de `Include` niet bovenaan, dan kunnen je eigen regels de homelab-regels
overschaduwen: ssh neemt de eerste waarde die hij vindt.

Is de Proxmox-API even weg, dan laat de rol `~/.ssh/config.d/homelab` staan
zoals het was, in plaats van een bijna lege te schrijven.

### Waarom twee vault-wachtwoorden

Minder schade bij een lek:

| Wachtwoord | Opent | Lekt het, dan moet je |
| --- | --- | --- |
| `infra` | inventory-vaults, `homelab.proxmox.yml`, Semaphore-config | hypervisor, DNS en back-ups roteren |
| `stacks` | `files/env/*.env` | de logins van de apps roteren |

`bin/vault-pass-client` leest ze uit `~/.ansible/`, dus je typt ze nooit. De
`semaphore`-rol zet ze ook op Semaphore, dus een back-up van ct 104 bevat ze.
Bewaar ze toch apart.

### Waarom de pre-commit hook

Een gecommit geheim blijft in de git-historie, ook als je het bestand weggooit.
CI ziet het pas na de push, als het al op GitHub staat.
