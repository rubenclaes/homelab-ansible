# Deze docs

Deze site: waar de pagina's vandaan komen en hoe je hem bijwerkt.

## De docs-site bijwerken

Je veranderde iets in de inventory of een pagina. `playbooks/docs.yml` maakt
de pagina's onder Homelab opnieuw, bouwt de site en zet hem op `caddy`.

<Steps>

#### Commit en push je wijziging eerst

```bash filename="laptop"
git add inventory docs-site && git commit -m '...' && git push
```

Semaphore bouwt de site elke ochtend opnieuw, uit git: wat je alleen lokaal
hebt, staat de volgende ochtend weer niet online.

#### Bouw en publiceer

```bash filename="laptop"
ansible-playbook playbooks/docs.yml
```

Verzamelt eerst facts van `linux:macs`, genereert de pagina's, en draait dan
`npm ci` en `npm run build` op je eigen machine; alleen het resultaat gaat naar
de `caddy`-host.

#### Kijk de site na

Open [docs.neodata.be](https://docs.neodata.be). Werkt alleen vanaf het LAN of
de tailnet.

</Steps>

Draai dit na elke wijziging in de inventory: een site die iets beweert wat
niet meer waar is, is erger dan geen documentatie, want je gelooft hem.

Faalt `docs.yml` op "De inventory is incompleet"? Dan laadde `homelab.proxmox.yml`
niet (API plat, token verlopen). Controleer met `ansible-inventory --graph`;
er is dan niets geschreven. Zie [Guests en API-token](/proxmox/beheren/#guests-en-api-token-checken).

## Wat waar vandaan komt

[Machines](/homelab/machines/) en [Toestellen](/homelab/toestellen/) maakt
`docs.yml` helemaal zelf. Bewerk die nooit: de volgende run overschrijft ze.
Pas de bron aan.

Een dienstpagina is half-half. De feiten — adres, host, poort, stack, groepen —
staan in één blok tussen twee MDX-commentaren:

```mdx filename="homelab/diensten/vault.mdx"
{/* BEGIN feiten uit de inventory — geschreven door docs.yml */}
...
{/* END feiten uit de inventory — geschreven door docs.yml */}
```

Dat blok is van `docs.yml`, en elke run schrijft hij het opnieuw, waar het op
de pagina ook staat. **Alles buiten het blok is van jou** en blijft staan: het
runbook van die dienst, zijn naslagtabel met paden die niet in de inventory
staan, zijn `## Goed om te weten`. Een nieuwe dienst krijgt vanzelf een pagina
met alleen dat blok erop.

Het bestand heet naar de route, niet naar de app: Vaultwarden staat in
`vault.mdx`, Outline in `wiki.mdx`, Immich in `photos.mdx`.

| Pagina | Bron |
| --- | --- |
| [Diensten](/homelab/diensten/), één pagina per dienst | het blok uit `caddy_sites` in `inventory/host_vars/caddy/main.yml`, plus `docker_services_without_route` van elke docker-host; de uitleg eromheen met de hand |
| [Machines](/homelab/machines/) | `inventory/00-static.yml`, de Proxmox-guests die `homelab.proxmox.yml` live ophaalt (ook hun cores, geheugen en schijf) en elke `docker_stacks_list` |
| [Toestellen](/homelab/toestellen/) | UniFi (Client Devices). Is UniFi onbereikbaar, dan blijft de vorige versie staan |
| Alle andere pagina's | met de hand geschreven, in `docs-site/content/` |

Een dienst die uit de inventory verdwijnt, laat geen pagina achter die er nog
live uitziet: die wordt opgeruimd, pas nadat de rest opnieuw gemaakt is. Staat
er uitleg op, dan blijft hij wél staan en zegt de run dat — handwerk gooit een
playbook niet weg.

## Zo schrijf je een pagina

| Regel | Waarom |
| --- | --- |
| per onderwerp een pagina, per geval een `##`, stappen in `<Steps>` met `####`-koppen | de koppen rechts zijn de inhoudstafel |
| uitleg over één dienst hoort op zijn pagina onder Diensten, niet apart | tot 30-09 stond Vaultwarden onder Docker en `vault` onder Diensten: twee pagina's voor één ding |
| een korte intro van 2-3 zinnen, geen `##` die de titel herhaalt | je bent meteen bij de eerste stap |
| per stap een commando en hoogstens 1-2 zinnen | het waarom staat onderaan |
| onderaan `## Goed om te weten` met de waaroms en de geschiedenis | de stappen blijven kort, de afweging gaat niet verloren |
| naslag (velden, vlaggen, "na X draai Y") als tabel | opzoeken, niet lezen |
| elk feit op één plek; elders een link | twee kopieën lopen uit elkaar |
| geen tijden van Semaphore buiten [Semaphore](/semaphore/) | die veranderen, en dan klopt de rest niet meer |
| een rood kader (`Callout`) alleen bij iets onomkeerbaars | anders lees je ze niet meer |
| elk codeblok `filename="<host>"`: waar je het draait (`laptop`, `pve01`…) | geen twijfel op welke machine |
| een regel die je niet mag overslaan: `{N}` na de filename | in plaats van een waarschuwing eronder |
