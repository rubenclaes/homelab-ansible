# Ansible-sleutel kwijt

De `ansible`-sleutel is weg, en er is nergens nog een kopie: niet op een
andere laptop, niet in de wachtwoordkluis.

## De ansible-sleutel is kwijt

Alleen als er echt nergens nog een kopie is: niet op een andere Mac, niet in
de wachtwoordkluis. Heb je wel een kopie, zet die dan gewoon terug op
`~/.ssh/ansible_ed25519` (zie [Werkplek → Laptop](/ansible/laptop/)).

**Let op:** `-u root -k` (inloggen met wachtwoord) helpt je hier **niet**. De baseline zet
`PasswordAuthentication no`, dus elke host weigert wachtwoorden. Je komt er
alleen nog in via de hypervisor of de console.

<Steps>

#### Maak een nieuwe sleutel

```bash filename="laptop"
ssh-keygen -t ed25519 -f ~/.ssh/ansible_ed25519 -C "ansible@homelab"
```

#### Zet hem in elke container

Als root op `pve01` (via het Proxmox-scherm → Shell), per container:

```bash filename="pve01"
pct exec <vmid> -- tee -a /home/ansible/.ssh/authorized_keys <<< "<inhoud van ansible_ed25519.pub>"
```

De vmids staan in `tofu/proxmox/containers.tf` (104 semaphore, 106 caddy,
107 adguard, 108 tailscale).

#### Zet hem in de VM's, pve01 en de Mac mini

- **VM's** (`pbs`, `docker`, `docker-grafana-stack`): via de console in het
  Proxmox-scherm, in `/home/ansible/.ssh/authorized_keys`.
- **`pve01`** zelf: via de Shell in het Proxmox-scherm, zelfde bestand.
- **`macmini`**: Ansible logt daar in als `rubenclaes`, dus in
  `~/.ssh/authorized_keys` van die gebruiker.

#### Zet de nieuwe publieke sleutel in de inventory

```bash filename="laptop"
$EDITOR tofu/proxmox/containers.tf   # ansible_pubkey, onderaan local
```

Anders krijgt elke nieuw gebouwde container de oude sleutel mee. Een plan
toont hier niets: de sleutel telt alleen bij het maken van een container.

#### Commit en push de nieuwe sleutel

```bash filename="laptop"
git add tofu/proxmox/containers.tf
git commit -m 'Nieuwe ansible-sleutel'
git push
```

#### Test

```bash filename="laptop"
ansible all -m ping
```

#### Bewaar de nieuwe sleutel

Zet een kopie in de wachtwoordkluis, zodat je dit nooit meer moet doen.

</Steps>
