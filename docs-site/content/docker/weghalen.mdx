# Dienst weghalen

Een Docker-app die weg mag.

**Let op:** Een container stoppen is het makkelijke deel. Wat je vergeet is de rest: een
route die blijft staan, een stack die de volgende run terugzet, een wachtwoord
dat nog geldig is. Daarom begint het met **zoeken**.

## Een Docker-app weghalen

Voorbeeld: `termix` uit de stack `utils`.

<Steps>

#### Zoek overal waar hij staat

In beide repo's, en op de docker-host:

```bash filename="laptop"
grep -rniI termix --exclude-dir=node_modules --exclude-dir=.git . ~/Development/containers
ssh docker 'sudo docker ps -a --filter name=termix'
ssh docker "sudo docker inspect -f '{{range .Mounts}}{{.Source}} {{end}}' utils-termix"
ssh docker 'ls /opt/containers/data | grep -i termix'
```

Schrijf de datamap op die `docker inspect` toont: na de volgende stappen is
de container weg en kan je het niet meer vragen. De `ls` vindt oude mappen van
een vorige opzet. Bij termix stond er naast `data/utils/termix` nog een
`data/termix` van december 2025.

Kijk ook buiten git, want dit vind je niet met grep:

| Waar | Wat je zoekt |
| --- | --- |
| Pocket ID (`id.neodata.be`) | een OIDC-client voor de app |
| NeoGate | een toegang die mensen voor de app krijgen |
| Semaphore | een template die de app raakt |
| `files/env/<stack>.env` | variabelen die alleen deze app gebruikt (`ansible-vault edit`) |

#### Haal de route weg

Verwijder zijn regel uit `caddy_sites` in `inventory/host_vars/caddy/main.yml`, dan:

```bash filename="laptop"
ansible-playbook playbooks/caddy.yml --check --diff   # alleen zijn blok verdwijnt
ansible-playbook playbooks/caddy.yml
```

Eerst de route, dan de container: zo krijgt niemand een foutpagina van een
dienst die half weg is.

#### Haal hem uit de compose

In de `containers`-repo: verwijder zijn blok onder `services:` in
`stacks/<stack>/docker-compose.yml`. Commit en **push**: de docker-host haalt de
compose van GitHub, niet van je laptop.

Is het de laatste dienst van de stack, dan gaat de hele stack weg. Doe dan
**eerst** een `down` op de host, en haal daarna de map uit de repo, de stack
uit `docker_stacks_list` in `inventory/host_vars/docker.yml` en
`files/env/<stack>.env` weg:

```bash filename="laptop"
ssh docker 'cd /opt/containers/stacks/<stack> && sudo docker compose down'
```

`remove_orphans` helpt hier niet: een stack die niet meer in
`docker_stacks_list` staat, bekijkt de rol niet meer, dus zijn containers
blijven gewoon draaien. De lege map `/opt/containers/stacks/<stack>` blijft
ook staan; die gaat mee weg in de datastap.

#### Laat stacks.yml de container opruimen

```bash filename="laptop"
ansible-playbook playbooks/stacks.yml --limit docker
```

De rol draait `docker compose up` met `remove_orphans`: een dienst die niet
meer in de compose staat, wordt gestopt en verwijderd. Hetzelfde playbook
haalt ook zijn tegel van home.neodata.be; zijn regel in `homepage_tiles` mag
je weggooien (de grep in de eerste stap vond hem).

#### Gooi de data weg

De map(pen) die je in de eerste stap opschreef:

```bash filename="laptop"
ssh docker 'sudo rm -rf /opt/containers/data/utils/termix /opt/containers/data/termix'
```

Dit is de enige stap die je niet terugdraait vanuit git. PBS heeft de data nog
in zijn back-ups van `docker`, tot die door de prune verdwijnen.

#### Ruim op buiten git

Wat je in de eerste stap vond: de OIDC-client in Pocket ID, de toegang in
NeoGate, variabelen in de `.env`. Een wachtwoord of sleutel die in de app zelf
stond, is daarmee niet ongeldig: verander hem daar waar hij ook gebruikt werd.

#### Docs, commit en push

```bash filename="laptop"
ansible-playbook playbooks/docs.yml
git add -A && git commit -m "chore: remove <app>" && git push
```

`docs.yml` haalt de pagina van de dienst zelf weg, want die komt uit
`caddy_sites`.

#### Test

```bash filename="laptop"
curl -sI https://<app>.neodata.be          # geen antwoord meer
ansible-playbook playbooks/smoketest.yml   # de rest werkt nog
```

</Steps>

## Goed om te weten

### Waarom zoeken de eerste stap is

Een dienst laat sporen na op plekken die niet in deze repo staan: de compose
in `containers`, een OIDC-client, een `.env`. Bij termix bleek het mee te
vallen (één compose-blok, één route, 180 KB data), maar dat wist je pas na het
zoeken. Een vergeten route is een foutpagina. Een vergeten OIDC-client is een
login die nog werkt voor een app die er niet meer is.

### Waarom de volgorde route → container → data

Elke stap is terug te draaien tot de laatste. De route en de compose zet je
terug met `git revert`. De data niet: die haal je alleen nog uit PBS. Door die
als laatste te doen, heb je tot het einde een weg terug.

### Waarom er geen playbook is dat alles weghaalt

Omdat de sporen buiten git liggen (Pocket ID, NeoGate, UniFi, Tailscale), zou
zo'n playbook maar de helft doen en de indruk geven dat het alles deed. Een
lijst die je afloopt is hier eerlijker.
