# Een nieuwe machine op pve01

Gebruik dit als je een **extra machine** op pve01 nodig hebt: een container
(LXC) of een virtuele machine (VM).

## Welk geval ben jij?

| Jouw situatie | Voorbeeld | Ga naar |
| --- | --- | --- |
| Je wil een **nieuwe container** voor software die een eigen machine hoort te hebben | Vaultwarden op een eigen LXC | [Nieuwe container](/runbooks/nieuwe-guest/container/) |
| Een container die **al in de lijst staat** is weg en je wil hem opnieuw bouwen | `adguard` na een herinstallatie van pve01 | [Container herbouwen](/runbooks/disaster-recovery/container-herbouwen/) |
| Je hebt echt een **virtuele machine** nodig (eigen kernel, eigen OS) | zoals `haos` of `docker` | [Virtuele machine](/runbooks/nieuwe-guest/vm/) |
| Je wil **één programma uit een Docker-image** dat moet blijven werken als de docker-VM plat ligt | `ntfy` | [OCI-container](/runbooks/nieuwe-guest/oci-container/) |

<Callout type="info">
Wil je gewoon een **Docker-app** draaien (Memos, Jellyfin…)? Dan heb je **geen
nieuwe machine** nodig. Die komt op de bestaande machine `docker`. Volg
[Dienst toevoegen → Nieuwe Docker-app](/runbooks/dienst-toevoegen/docker-app/).
</Callout>

Twijfel je tussen container en VM: kies de **container**. Die start in een
seconde, kost nauwelijks geheugen, en het hele pad is geautomatiseerd. Een VM
is voor als het echt niet anders kan, bv. een eigen besturingssysteem zoals
Home Assistant OS.

Na een container of VM ga je verder met [Afwerken](/runbooks/nieuwe-guest/afwerken/):
dienst erop, adres, back-up, commit, docs. Een OCI-container heeft zijn
eigen, kortere pad: de dienst ís de container.

## Woorden die je nodig hebt

- **Guest** — alles wat op pve01 draait: een container of een VM.
- **vmid** — het unieke nummer van een guest in Proxmox (bv. `107` is `adguard`).
- **`pve_lxcs`** — de lijst met containers in `inventory/group_vars/proxmox/lxcs.yml`. Wat daar niet in staat, kan het playbook niet bouwen.
- **Baseline** — het minimum dat elke Linux-machine krijgt: tijdzone, basispakketten, automatische beveiligingsupdates, SSH dichtgetimmerd.
- **Vault** — de versleutelde bestanden met wachtwoorden. Je hebt `~/.ansible/vault_pass_infra` en `~/.ansible/vault_pass_stacks` op je werkstation nodig (zie de README).

## Als het misgaat

| Wat je ziet | Wat het is |
| --- | --- |
| Het playbook stopt meteen met een lijst namen | Je naam staat niet in `pve_lxcs`. Zet hem erbij en draai opnieuw |
| Het blijft hangen bij "Wait for SSH" (3 minuten) | De container start niet, of het adres klopt niet. Kijk in het Proxmox-scherm of hij draait en welk adres hij heeft |
| Een fout over een hostkey | Er stond al een andere machine op dat adres. `ssh-keygen -R <adres>` en opnieuw |
| Een fout over het vault-wachtwoord | `~/.ansible/vault_pass_infra` ontbreekt of klopt niet. Zie de README |
| Een VM staat niet in de inventory | De guest agent draait niet. Zie [Virtuele machine](/runbooks/nieuwe-guest/vm/#controleer-dat-ansible-hem-ziet) |
| Een OCI-container staat meteen weer op `stopped` | Meestal een ontbrekend `entrypoint`-argument of een map die niet bestaat. Zet `lxc.console.logfile: /tmp/ct.log` onderaan `/etc/pve/lxc/<vmid>.conf`, start hem, en lees dat bestand. Haal de regel daarna weer weg |

Een half gebouwde container is niet erg: het playbook mag altijd opnieuw. Wat
al bestaat wordt niet nog eens gemaakt.
