# Een container opnieuw bouwen

Voor een container die in `pve_lxcs` staat maar stuk of weg is, en waar niets
unieks op staat: `caddy` en `tailscale`. Nieuw bouwen gaat sneller dan een
back-up terugzetten, en is schoner.

<Callout type="warning">
Dit geeft je een **lege** container met de juiste instellingen. Heb je de data
nodig (instellingen, databases), volg dan
[Terugzetten uit back-up](/runbooks/disaster-recovery/terugzetten/).
Voor `adguard`, `semaphore` e.a. is dat bijna altijd wat je wil.
</Callout>

Voorbeeld: `caddy` (ct 106).

<Steps>

### Gooi de oude weg (als hij nog half bestaat)

```bash
ssh pve01 'sudo pct stop 106; sudo pct destroy 106'
```

Het playbook maakt alleen wat ontbreekt. Een halve container blijft anders
gewoon staan.

### Bouw hem opnieuw

```bash
ansible-playbook playbooks/new-guest.yml -e guest=caddy
```

Maakt de container, zet het `ansible`-account erop en doet de baseline.
Meerdere tegelijk kwijt? Eén per keer, in deze volgorde: `adguard` (DNS),
`caddy` (de voordeur), `tailscale`, `semaphore`.

### Doe de handwerkstappen uit `lxcs.yml`

Sommige containers hebben instellingen die het API-token niet kan zetten. Die
staan als commentaar bij hun blok in `inventory/group_vars/proxmox/lxcs.yml`.
Nu: `tailscale` (108) en `adguard` (107), allebei voor `/dev/net/tun`.

Zet als root op pve01 deze twee regels onderaan `/etc/pve/lxc/<vmid>.conf`
(voorbeeld 108):

```bash
ssh -t pve01 'sudoedit /etc/pve/lxc/108.conf'
```

```
lxc.cgroup2.devices.allow: c 10:200 rwm
lxc.mount.entry: /dev/net/tun dev/net/tun none bind,create=file
```

```bash
ssh pve01 'sudo pct reboot 108'   # een mount-entry geldt pas na een herstart
```

Zonder dit start `tailscaled` niet: hij faalt stil in een herstartlus. Geen
playbook kan het voor je doen.

<Callout type="warning">
Niet met `pct set 108 -lxc.cgroup2.devices.allow …`: `pct set` weigert rauwe
`lxc.`-sleutels op deze Proxmox-versie ("400 unable to parse option"). Schrijf
de regels dus altijd rechtstreeks in het `.conf`-bestand.
</Callout>

### Zet de dienst terug

```bash
ansible-playbook playbooks/site.yml --limit caddy
```

Voor `semaphore`: `ansible-playbook playbooks/semaphore.yml`, niet
`site.yml --limit semaphore` (die faalt).

### Alleen bij `tailscale`: keur de route goed

Een opnieuw aangemelde `tailscale` biedt `192.168.0.0/24` opnieuw aan. Keur die
route goed in de Tailscale admin console, anders werkt toegang van buitenaf niet.

### Alleen bij `caddy`: zet de docs en het rapport terug

```bash
ansible-playbook playbooks/caddy-smoketest.yml
ansible-playbook playbooks/docs.yml       # docs.neodata.be staat op caddy
ansible-playbook playbooks/report.yml     # report.neodata.be ook
```

Een nieuwe `caddy` is leeg: de routes werken, maar deze site en het rapport
staan er pas weer na deze twee.

### Laat Semaphore de nieuwe machine vertrouwen

```bash
ansible-playbook playbooks/semaphore.yml
```

De nieuwe container heeft een nieuwe SSH-hostkey. Semaphore weigert hem tot
deze run. Niet met `--limit semaphore`: dan faalt hij.

</Steps>

<Callout type="info">
`adguard` herbouwen heeft nog extra handwerk (setup-wizard, upstreams, de
wildcard-rewrite). Volg daarvoor [Geen DNS](/runbooks/disaster-recovery/geen-dns/).
</Callout>
