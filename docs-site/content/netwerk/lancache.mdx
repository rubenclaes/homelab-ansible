# LANCache

Voor een LAN party: een game komt één keer via internet binnen, en iedereen
daarna krijgt hem uit de cache, aan de snelheid van het netwerk. Buiten een
party staat LANCache uit.

## Aanzetten

<Steps>

#### Zet hem aan

```bash filename="laptop"
ansible-playbook playbooks/lancache.yml -e lancache=on
```

Start de container op pve01 en wacht tot hij antwoordt. Pas dan stuurt AdGuard
de downloads van Steam, Epic, Battle.net, Riot, EA, Ubisoft, Xbox, PlayStation
en Nintendo naar hem.

#### Kijk of hij werkt

```bash filename="laptop"
dig +short lancache.steamcontent.com @192.168.0.29
```

Geeft `192.168.0.33`. Steam op een pc die al openstond: even opnieuw starten,
want die onthoudt het oude adres.

</Steps>

## Vooraf vullen

De avond voor de party: zet de Steam-games die jullie spelen al in de cache.
Dan krijgt ook de eerste vriend ze aan LAN-snelheid. Reken op 30 à 45 minuten
per 100 GB.

<Steps>

#### Eén keer: log in en kies de games

```bash filename="laptop"
ssh -t docker 'sudo install -d -m 700 /opt/containers/data/steamprefill && sudo docker run -it --rm --dns 192.168.0.29 -v /opt/containers/data/steamprefill:/Config tpill90/steam-lancache-prefill:v3.7.2 select-apps'
```

Log in met je Steam-account (wachtwoord en de code van Steam Guard), en vink
de games aan. Vraagt hij op het einde of hij meteen moet vullen: zeg nee, dat
doet de volgende stap (met LANCache aan). Je keuze aanpassen: hetzelfde
commando opnieuw.

#### Vul de cache

```bash filename="laptop"
ansible-playbook playbooks/lancache-prefill.yml
```

Zet LANCache aan, haalt elke gekozen game één keer door de cache, en zet hem
weer uit. Met `-e lancache_after=on` blijft hij aan, voor als de party meteen
begint. Een game die al in de cache zit en niet veranderd is, slaat hij over.

</Steps>

## Uitzetten

```bash filename="laptop"
ansible-playbook playbooks/lancache.yml -e lancache=off
```

Eerst gaat de rewrite in AdGuard weg, dan stopt de container. Downloads gaan
weer gewoon via internet. De cache blijft staan voor de volgende party.

Staat Steam nog open, start het dan opnieuw: Steam kijkt alleen bij het
opstarten of er een LANCache is, en blijft er anders naartoe sturen. Andere
launchers volgen de DNS van de computer; gaat het daar niet meteen, wacht een
minuut of doe `ipconfig /flushdns` op Windows.

## Nakijken wat er uit de cache komt

```bash filename="laptop"
ssh pve01 'sudo pct exec 110 -- tail -f /data/logs/access.log'
```

`HIT` kwam uit de cache, `MISS` via internet (en staat er nu wel in).

## Goed om te weten

| Wat | Waarde |
| --- | --- |
| Container | ct 110 `lancache`, `192.168.0.33`, op pve01 |
| Cache | 600 GB op `vm-hdd`, nginx ruimt op vanaf 550 GB |
| Instellingen | `pve_oci_lxcs` in `inventory/group_vars/proxmox/lxcs.yml`; het adres in `inventory/group_vars/all/lancache.yml` |
| Welke domeinen | `lancache_domains` in `roles/lancache/defaults/main.yml` |

### Waarom alleen tijdens een party

Staat LANCache aan en ligt hij plat, dan stuurt AdGuard elke game-download
naar een adres waar niets antwoordt, en kan niemand in huis nog iets
downloaden. Daarom staat hij uit tenzij je hem nodig hebt, en start hij ook
niet vanzelf als pve01 herstart. `lancache.yml` zet de rewrite pas als de
cache antwoordt.

### pve01 herstart tijdens een party

Dan staat de container uit, maar wijst DNS nog naar hem. De dagelijkse
smoketest wordt daar rood van. Draai gewoon opnieuw `-e lancache=on`, of
`off` als de party voorbij is.

### Waarom niet in de back-up

De cache vult zichzelf opnieuw bij de eerste download. 600 GB elke nacht naar
PBS wegschrijven kost meer dan het oplevert. De dagelijkse back-upjob sluit
ct 110 uit. Let op: opnieuw bouwen (`proxmox-oci.yml -e
proxmox_oci_recreate=true`, of `pct destroy --purge 110`) haalt 110 ook uit
die uitsluiting. Draai daarna `proxmox-datacenter.yml`, die zet hem terug.

### Waarom AdGuard en niet de DNS van LANCache

LANCache heeft zelf een DNS-container, maar dan zou het huis tijdens een party
twee DNS-servers hebben. AdGuard krijgt gewoon een rewrite per downloaddomein.
LANCache zelf vraagt zijn namen aan Quad9, niet aan AdGuard: anders zou hij de
omgeleide namen naar zichzelf terugkrijgen.

### Bestanden die het image weggooit, staan er toch

De OCI-import van Proxmox voert de verwijderingen uit latere lagen van een
image niet uit. Bij LANCache bleef zo een standaard-nginx-site staan die op
alles een 404 gaf. `remove_paths` bij zijn entry in `pve_oci_lxcs` haalt die
bestanden weg na het aanmaken, ook bij een herbouw.

### Vooraf vullen draait op docker, niet op je laptop

`docker` hangt met een kabel aan de 2,5 Gbit van pve01; je laptop zit vaak op
wifi. De container krijgt `--dns 192.168.0.29`: `docker` heeft `1.1.1.1` als
tweede nameserver, en een antwoord van daar laat SteamPrefill naast de cache
downloaden. De login is een token, geen wachtwoord; hij staat in
`/opt/containers/data/steamprefill` en gaat versleuteld mee in de back-up.

### Alleen HTTP

Steam, Epic en de andere winkels leveren games over HTTP, en die kan LANCache
bewaren. Wat over HTTPS komt (inloggen, de winkel zelf) gaat gewoon langs.
