# Adressen (Caddy)

Caddy geeft elke dienst een adres zoals `naam.neodata.be`. Hier voeg je een
adres toe of haal je het weg, werk je Caddy bij en doorzoek je de logs.

## Alleen een adres

De dienst **draait al**, je wil hem alleen bereiken op `naam.neodata.be` in
plaats van op `192.168.0.26:32400`. Je hoeft niets te installeren. Je voegt
alleen een route toe.

Voorbeeld: Plex draait op de Mac mini op poort 32400.

<Steps>

#### Voeg één regel toe aan `caddy_sites`

```bash filename="laptop"
$EDITOR inventory/host_vars/caddy/main.yml
```

Zet onder `caddy_sites:`:

```yaml filename="inventory/host_vars/caddy/main.yml"
  - { name: plex, host: macmini, port: 32400, desc: "Plex — de hoofdtaak van de Mac mini" }
```

Wat elk veld doet: zie [Alle velden van een route](#alle-velden-van-een-route).
Staat de machine niet in de inventory (bv. een printer)? Gebruik dan
`upstream: "192.168.0.50:80"` in plaats van `host` en `port`.

#### Zet hem live en test

```bash filename="laptop"
ansible-playbook playbooks/caddy.yml
ansible-playbook playbooks/smoketest.yml --tags caddy
ansible-playbook playbooks/stacks.yml --tags homepage   # de tegel op home.neodata.be
ansible-playbook playbooks/docs.yml
```

#### Commit en push

```bash filename="laptop"
git add inventory && git commit -m 'Route voor plex' && git push
```

</Steps>

### Alle velden van een route

| Veld | Doet |
| --- | --- |
| `name` | wordt `name.neodata.be` |
| `host` | een **inventory-hostnaam**; zijn adres wordt de bestemming |
| `port` | de poort waar de dienst luistert |
| `desc` | korte uitleg, komt op deze docs-site en op home.neodata.be |
| `stack` | de stack uit `docker_stacks_list` waar hij in zit. Weglaten als het geen beheerde stack is (Plex, een VM) |
| `upstream` | alternatief voor `host` + `port`, voor iets dat niet in de inventory staat |
| `https` | de dienst praat zelf HTTPS (met een zelfgemaakt certificaat) |
| `host_header` | stuur de oorspronkelijke `Host`-header door |
| `forwarded` | zet `X-Real-IP` en `X-Forwarded-*` erbij (Home Assistant wil dit) |
| `auth` | login via Pocket ID ervoor, alleen voor die groep: `admin` of `gezin`. Zie [Een login ervoor](#een-login-ervoor) |
| `auth_skip` | paden zonder die login, bv. `['/api/*']` voor een API met een eigen sleutel |

Waarom `host` en niet gewoon een IP? Verhuist een machine naar een ander adres,
dan pas je dat op één plek aan en volgen alle routes vanzelf.

## Een login ervoor

Voor apps zonder eigen login via Pocket ID (code-server, de *arr-apps,
Prometheus, qBittorrent, de tools). Caddy vraagt bij elk verzoek aan
oauth2-proxy, dat naast Caddy draait, of je aangemeld bent en in de juiste
groep zit. Zo niet, dan stuurt hij je naar `auth.neodata.be` en daarna terug.
Eén keer aanmelden geldt voor alle zulke apps.

Zet het veld erbij in `caddy_sites`:

```yaml
  - { name: code, auth: admin, host: docker, port: 8443, ... }
  - { name: sonarr, auth: admin, auth_skip: ['/api/*'], host: docker, port: 8989, ... }
```

en dan `ansible-playbook playbooks/caddy.yml`.

| Groep | Wie |
| --- | --- |
| `admin` | alleen beheer: code-server, Sonarr, Radarr, Prowlarr, Bazarr, Prometheus, qBittorrent |
| `gezin` | wie hier woont: IT-Tools, MeTube, BentoPDF, PairDrop, OpenBooks |

Gebruikt een andere app de API via het publieke adres, zet die paden dan in
`auth_skip`. NeoGate praat zo met Sonarr en Radarr; hun API blijft beschermd
met de eigen API-sleutel.

### Niet om de login heen

Sonarr, Radarr, Prowlarr, Bazarr en code-server vragen zelf geen login meer
(of nooit gedaan) van een LAN-adres. Daarom laat de docker-host hun poorten
alleen nog van Caddy toe: een firewall in de Docker-keten `DOCKER-USER`, uit
`docker_stacks_proxy_only_ports` in `inventory/host_vars/docker/main.yml`.
Zonder die regel kon iedereen op de wifi via `192.168.0.15:8989` rechtstreeks
binnen. De apps onderling praten via het Docker-netwerk en merken er niets van.

qBittorrent draait met host-netwerk, en die regel raakt hem niet. Hij houdt zijn
eigen login; Caddy staat op zijn whitelist, zodat je via
`torrent.neodata.be` maar één keer inlogt.

Een app beschermen die ook zelf geen login vraagt: `auth:` in `caddy_sites`
**en** de poort in `docker_stacks_proxy_only_ports`.

### Ligt Pocket ID of oauth2-proxy plat?

| App | Noodtoegang |
| --- | --- |
| Sonarr, Radarr, Prowlarr, Bazarr, code-server | `ssh -L 8989:localhost:8989 docker` en dan `http://localhost:8989` (andere poort, zelfde manier) |
| qBittorrent, de tools | rechtstreeks op `192.168.0.15:<poort>` |

## Alleen het adres weghalen

De dienst zelf blijft, alleen `naam.neodata.be` gaat weg.

<Steps>

#### Haal de route weg

Verwijder de regel uit `caddy_sites` en draai `caddy.yml`, zoals hierboven.
Daarna `ansible-playbook playbooks/stacks.yml --tags homepage`, zodat ook de
tegel op home.neodata.be weggaat.

#### Docs, commit en push

```bash filename="laptop"
ansible-playbook playbooks/docs.yml
git add -A && git commit -m "chore: drop the <naam> route" && git push
```

#### Het Fixed IP (optioneel)

Had het toestel alleen een Fixed IP in UniFi omdat er een route naar wees? Dan
mag dat weg. `unifi-routes.yml` vraagt het niet meer.

</Steps>

## Caddy

`caddy` doet **niet** mee met `update.yml`: het pakket staat vast
(`baseline_held_packages` in `inventory/host_vars/caddy/main.yml`). Upgraden
doe je bewust, met een eigen playbook.
[Waarom](#waarom-caddy-vaststaat).

<Steps>

#### Upgrade Caddy

```bash filename="laptop"
ansible-playbook playbooks/caddy-upgrade.yml
```

Dit draait `caddy upgrade`, herstart Caddy en controleert dat de
Cloudflare-module er nog in zit. Ontbreekt die, dan faalt hij en zegt hij
welk commando het herstelt.

#### Controleer de uitkomst

De smoketest zit al in dit playbook. Is "Smoke test all Caddy sites" groen,
dan werkt elk `*.neodata.be`-adres nog.

</Steps>

**Let op:** Gebruik niet `ansible caddy -a "caddy upgrade"`. Dat vervangt de binary, maar
herstart Caddy niet en controleert niets.

## Caddy-logs doorzoeken

Elk verzoek van buiten gaat langs `caddy`. Grafana Alloy stuurt die logs naar
Loki in de monitoring-stack.

<Steps>

#### Open Grafana

Ga naar [monitoring.neodata.be](https://monitoring.neodata.be) en zoek in Loki.

#### Kies wat je wil zien

| Query | Wat je ziet |
| --- | --- |
| `{job="caddy"}` | elk verzoek dat de reverse proxy afhandelde |
| `{job="caddy-runtime"}` | wat Caddy zelf meldt: certificaten, herladen, fouten |

#### Filter met `| json`

```text filename="Grafana → Explore"
{job="caddy"} | json | status >= 500
{job="caddy"} | json | request_host = "plex.neodata.be"
```

</Steps>

### Andere logbestanden versturen

<Steps>

#### Pas de lijst aan

```bash filename="laptop"
$EDITOR inventory/host_vars/caddy/main.yml   # alloy_log_targets
```

Welke hosts een agent krijgen, staat in de groep `alloy_hosts` in
`inventory/00-static.yml`. Nu is dat alleen `caddy`.

#### Zet het live

```bash filename="laptop"
ansible-playbook playbooks/alloy.yml
```

#### Commit en push de logbestanden

```bash filename="laptop"
git add inventory && git commit -m 'Alloy: extra logbestand' && git push
```

</Steps>

**Let op:** Zet de Docker-hosts **niet** in `alloy_hosts`. De Alloy ín de monitoring-stack
haalt hun containerlogs al via de Docker-socket; een tweede agent stuurt alles
dubbel.

Waarom `caddy_log_mode` op `0640` staat en een `reload` niet volstaat:
[Goed om te weten](#goed-om-te-weten).

## Goed om te weten

### oauth2-proxy en "email isn't verified"

Pocket ID heeft geen mailserver, dus geen enkel adres is "geverifieerd", en
oauth2-proxy weigert dat standaard (een 500 na het aanmelden). Daarom staat
`insecure_oidc_allow_unverified_email` aan: het adres beslist hier niets, de
groep wel. De rol staat in `roles/oauth2_proxy`, de client in
`tofu/pocketid/clients.tf`, de geheimen in `host_vars/caddy/vault.yml`.

### De login-cookie gaat naar élke app

oauth2-proxy zet zijn cookie op `.neodata.be`, zodat één login voor alle
apps geldt. Je browser stuurt hem daardoor ook mee naar apps zónder login,
en hij is een paar KB groot (de tokens van Pocket ID zitten erin). Een app
die maar 4 KB aan headers aanvaardt, antwoordt dan `431 Request Header
Fields Too Large`. Zo gaf NeoGate op 27 september 2026 "geen verbinding" in
elke tegel, tot het 16 KB aanvaardde. Zie je ergens een 431 in de
Caddy-logs, dan is dit de eerste verdachte. Snel verhelpen: de
`_oauth2_proxy`-cookies van `neodata.be` wissen in je browser.

### Waarom Caddy vaststaat

Caddy is hier een eigen build met de plugin `caddy-dns/cloudflare`. Een gewone
`apt full-upgrade` verving hem ooit door de standaardversie. Die weigert te
starten met de Cloudflare-module in de Caddyfile, en elk `*.neodata.be`-adres
lag plat. `apt full-upgrade` en `cleanup.yml` respecteren de hold, dus ze raken
hem niet aan. `caddy upgrade` bouwt opnieuw mét de plugins.

### Alloy en de rechten op de logbestanden

Alloy draait als gebruiker `alloy`, niet als root, en leest via groep `caddy`.
Daarom staat `caddy_log_mode` op `0640`. Caddy past die mode toe bij het
**openen** van een bestand: na `systemctl reload caddy` bleef het `0600`, pas
na `systemctl restart caddy` (of de rotatie om middernacht) werd het `0640`.

De regels zijn JSON en krijgen geen label per statuscode of pad, omdat Loki op
labels indexeert: pel af bij het zoeken, niet bij het schrijven.
