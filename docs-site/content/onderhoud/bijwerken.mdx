# Bijwerken

De guests, pve01 en de Macs bijwerken. Patchen van de guests gebeurt vanzelf,
herstarten **nooit**: dat moment kies jij. Wat er openstaat, zie je in het
[Gezondheidsrapport](/onderhoud/nakijken/#gezondheidsrapport), tabblad
**Updates**.

Caddy en de OCI-containers doen niet mee met `update.yml`: zie
[Caddy bijwerken](/netwerk/caddy/#caddy-bijwerken) en
[Een OCI-container bijwerken](/proxmox/oci/#een-oci-container-bijwerken).

## Guests patchen en herstarten

Semaphore patcht de guests elke week ("Update guests",
[schema](/semaphore/#wat-draait-er-vanzelf-en-wanneer)), behalve `semaphore`
zelf. Met de hand doe je het als je niet wil wachten, voor `semaphore`, of als
een guest `REBOOT NEEDED` meldt.

<Steps>

#### Patch de guests

```bash filename="laptop"
ansible-playbook playbooks/update.yml --limit guests      # alle guests
ansible-playbook playbooks/update.yml --limit semaphore   # alleen Semaphore
```

`apt full-upgrade`, één host na de andere, zonder herstart. Semaphore patch je
altijd vanaf je laptop ([waarom](/semaphore/#de-limits-in-de-templates)).

#### Kijk of er een herstart nodig is

Zoek in de output naar `REBOOT NEEDED`. Staat die er niet, dan ben je klaar.

#### Herstart wat het nodig heeft

```bash filename="laptop"
ansible-playbook playbooks/update.yml --limit docker -e allow_reboot=true   # één guest
ansible-playbook playbooks/update.yml --limit guests -e allow_reboot=true   # alle guests
```

Hij patcht eerst, en herstart alleen wie het nodig heeft. Herstart je
`docker`, dan liggen alle stacks erop even plat.

</Steps>

Alleen de VM's (`docker`, `pbs`, `docker-grafana-stack`) melden ooit een
herstart. Een LXC gebruikt de kernel van pve01: een nieuwe kernel voor de
LXC's is [pve01 herstarten](#pve01-bijwerken-en-herstarten).

## pve01 bijwerken en herstarten

Bijvoorbeeld voor een nieuwe Proxmox-kernel.

<Callout type="error">
**Nooit vanuit Semaphore.** Semaphore is een container óp pve01: een herstart
van pve01 doodt de job die hem gaf. Altijd vanaf je laptop.
</Callout>

<Steps>

#### Kies een moment waarop alles even weg mag

Een herstart van pve01 legt **elke guest** plat, ook DNS (`adguard`) en alle
`*.neodata.be`-adressen (`caddy`).

#### Patch en herstart

```bash filename="laptop"
ansible-playbook playbooks/update.yml --limit linux \
  -e allow_reboot=true -e allow_hypervisor_reboot=true
```

Eerst de guests, dan pas pve01. Je hebt **beide** flags nodig.

#### Controleer of alles terug is

```bash filename="laptop"
ansible-playbook playbooks/smoketest.yml   # werkt elk adres nog, antwoordt AdGuard nog?
```

</Steps>

Zonder de flags patcht een run pve01 gewoon mee, maar herstart hij niet: je
krijgt een melding dat hij een herstart nodig heeft.

## De Macs

Homebrew bijwerken op `mbp` en `macmini`. Semaphore doet de Macs niet
([waarom](#waarom-semaphore-de-macs-niet-doet)): draai dit vanaf je MacBook.

<Steps>

#### Werk de pakketten bij

```bash filename="laptop"
ansible-playbook playbooks/update.yml --limit macs   # beide Macs
ansible-playbook playbooks/update.yml --limit mbp    # alleen je MacBook
```

Dit is `brew upgrade --formula`: alleen pakketten, geen apps. De Mac mini
slaat zijn pakketten over ([waarom](#de-mac-mini-en-homebrew)) en zegt dat
elke run.

#### Ook de apps: zet de cask-flag aan

```bash filename="laptop"
ansible-playbook playbooks/update.yml --limit macs -e allow_cask_upgrade=true
```

Een open app kan even afgesloten worden. Apps die zichzelf updaten (Spotify,
Chromium) laat hij met rust.

#### Kijk of elke Mac aan de beurt kwam

De Macs gaan één voor één. Faalt er een, dan stopt de play en komt de
volgende niet meer aan de beurt, zonder dat het log dat zegt. Kijk per Mac in
de output.

</Steps>

macOS zelf werkt `update.yml` niet bij: het rapport toont wel welke
macOS-updates klaarliggen, installeren doe je met de hand op de Mac.

### Een cask die faalt op `sudo`

```
sudo: a terminal is required to read the password
Error: <naam>: Failure while executing; `/usr/bin/sudo -u root -E -- ...`
```

Doe die ene cask met de hand, mét terminal (`-t`):

```bash filename="laptop"
ssh -t rubenclaes@192.168.0.26 '/opt/homebrew/bin/brew upgrade --cask <naam>'   # of: uninstall --cask
```

Waarom `-K` niet helpt: [Casks die root nodig hebben](#casks-die-root-nodig-hebben).

## Ansible zelf

Ansible, ansible-lint en de collections draaien op drie plekken: je laptop,
CI en Semaphore. Alle drie installeren uit dezelfde twee bestanden, dus je
werkt de versie op één plek bij.

<Steps>

#### Zet de nieuwe versies in de repo

| Wat | Bestand | Waar vind je de nieuwste |
| --- | --- | --- |
| `ansible-core`, `ansible-lint` | `requirements.txt` (`==`) | [pypi.org](https://pypi.org/project/ansible-core/) |
| collections | `collections/requirements.yml` (de ondergrens, `>=`) | [galaxy.ansible.com](https://galaxy.ansible.com) |

#### Werk je laptop bij

```bash filename="laptop"
uv tool install --force --with-requirements requirements.txt \
  --with-executables-from ansible-lint ansible-core
ansible-galaxy collection install -r collections/requirements.yml
ansible-lint
```

#### Push, en werk Semaphore bij

CI pakt de nieuwe versies vanzelf op. Semaphore niet:

```bash filename="laptop"
ansible-playbook playbooks/semaphore.yml
```

</Steps>

## Alle flags

Allemaal standaard **uit**. Zonder flags wordt er gepatcht en verder niets.

| Variabele | Waar | Doet |
| --- | --- | --- |
| `allow_reboot` | commandline | herstart guests die het nodig hebben |
| `allow_hypervisor_reboot` | commandline | ook pve01; werkt alleen samen met `allow_reboot` |
| `allow_cask_upgrade` | commandline | ook de apps op de Macs |
| `macos_brew_upgrade` | `host_vars/<mac>/main.yml` | `false`: deze Mac krijgt geen pakket-upgrades |

## Goed om te weten

### Welke van de drie playbooks?

| Playbook | De vraag | Wat hij doet |
| --- | --- | --- |
| `site.yml` | staat alles er zoals beschreven? | installeert wat ontbreekt, haalt weg wat in een `*_absent`-lijst staat. Versies laat hij met rust |
| `update.yml` | zijn de versies actueel? | `apt full-upgrade` op Linux, `brew upgrade` op de Macs. Herstart alleen als je erom vraagt |
| `cleanup.yml` | valt er schijfruimte terug te winnen? | caches, oude images, verweesde pakketten. Rapporteert standaard alleen, zie [Opruimen](/onderhoud/opruimen/) |

Iets **weg** van een Mac (`macos_brew_packages_absent`, `macos_casks_absent`)
is dus `site.yml --tags macos`, niet `cleanup.yml`.

### Waarom de volgorde: guests, dan pve01, dan de Macs

`update.yml` heeft drie plays, elk met `serial: 1`: één host is klaar voor de
volgende begint, dus een mislukte upgrade sloopt één machine, niet alles.
Guests gaan vóór pve01, anders kan pve01 herstarten terwijl zijn guests nog
bezig zijn. De Macs komen laatst: op de MacBook draait `ansible` op de Python
van Homebrew, en een upgrade vervangt het programma dat op dat moment draait.

`allow_hypervisor_reboot` alleen doet niets. Zo kan een gewone run nooit per
ongeluk pve01 meenemen.

### Waarom Semaphore de Macs niet doet

Vanuit Semaphore is `mbp` de Semaphore-container, niet je MacBook
([uitleg](/semaphore/#de-limits-in-de-templates)). Daarom draait "Update
guests" met `--limit guests:!semaphore`.

### De Mac mini en Homebrew

De Mac mini draait macOS 14.6.1, en daarvoor bouwt Homebrew geen kant-en-klare
pakketten (bottles) meer: alles moet vanaf broncode, uren werk, en een deel
lukt niet. Daarom staat `macos_brew_upgrade: false` in
`inventory/host_vars/macmini/main.yml`. Casks werken wel, dat zijn
kant-en-klare apps. De pakketten komen terug na een nieuwere macOS.

### Casks die root nodig hebben

Sommige casks zetten bestanden onder `/Library`, en bij een upgrade roept brew
zelf `sudo` aan. Over SSH is er geen terminal, dus sudo kan geen wachtwoord
vragen. `-K` helpt niet: dat is het sudo-wachtwoord van Ansible, en Ansible
zit hier niet tussen.

Automatisch kan het wel (`SUDO_ASKPASS` met een scriptje dat het wachtwoord
uit de vault haalt), maar dan krijgt elke brew-taak op die Mac je
inlogwachtwoord, voor een handvol casks. Bewust niet gedaan.
