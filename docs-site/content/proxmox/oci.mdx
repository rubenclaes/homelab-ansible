# OCI-container

Eén programma uit een Docker-image, als eigen container op pve01, zonder
Docker ertussen: geen Debian, geen SSH, geen apt (sinds Proxmox 9.1, nog een
tech preview). Alleen voor iets kleins dat moet blijven werken als de machine
`docker` plat ligt. `ntfy` is het voorbeeld: wie meldt dat `docker` stuk is,
mag er niet zelf op draaien. Al de rest hoort op `docker`, met compose en
healthchecks.

## Een OCI-container maken

<Steps>

#### Zet hem in `pve_oci_lxcs`

In `inventory/group_vars/proxmox/lxcs.yml`, met een vaste `version`, nooit
`latest`. Kijk naar `ntfy` als voorbeeld. Twee dingen die je bij een nieuw
image moet nakijken:

- **`entrypoint`**: veel images hebben een `ENTRYPOINT` zonder argumenten.
  Kaal start dat de help en stopt meteen, zonder melding.
- **`volumes`**: elke map waar het programma naar schrijft en die niet in het
  image zit. Ontbreekt er een, dan stopt de container.

Zet alles wat moet blijven bestaan in `env`, niet op de schijf
([waarom](#updaten-is-opnieuw-bouwen)).

#### Bouw de OCI-container

```bash filename="laptop"
ansible-playbook playbooks/proxmox-oci.yml
```

De rol haalt het image op, maakt de container, zet `entrypoint` en `env`, en
start hem. Een tweede run doet niets.

#### Geef hem een naam (optioneel)

Zoals bij een gewone container, in `caddy_sites`: zie
[Afwerken → Geef hem een adres](/proxmox/afwerken/#geef-hem-een-adres-optioneel).
Geef hem een vaste `upstream` in plaats van alleen `host`: een gestopte
OCI-container heeft geen adres in de inventory, en dan faalt de Caddyfile
voor elke site. De container staat na de eerste run in de inventory, onder
`appliances`.

</Steps>

## Een OCI-container bijwerken

`ntfy` doet niet mee met `update.yml`: er zit geen apt in. Bijwerken is een
nieuwer image nemen en de container opnieuw bouwen.

<Steps>

#### Hoog de versie op

```bash filename="laptop"
$EDITOR inventory/group_vars/proxmox/lxcs.yml
```

In `pve_oci_lxcs`, het veld `version`. Een vaste versie, nooit `latest`: dan
weet je wat er draait, en een herbouw geeft je hetzelfde terug.

#### Kijk eerst wat er zou gebeuren

```bash filename="laptop"
ansible-playbook playbooks/proxmox-oci.yml
```

Zonder vlag verandert er niets: de rol waarschuwt alleen, meldt welke versie
draait en welke je vraagt, en alles blijft staan.

#### Bouw hem opnieuw

```bash filename="laptop"
ansible-playbook playbooks/proxmox-oci.yml -e proxmox_oci_recreate=true
```

De container **en zijn volumes** gaan weg en komen terug op het nieuwe image
([waarom dat mag](#updaten-is-opnieuw-bouwen)).

#### Commit en push

```bash filename="laptop"
git add inventory/group_vars/proxmox/lxcs.yml
git commit -m 'ntfy: nieuwe versie'
git push
```

</Steps>

## Een ntfy-token erbij

Elke app die meldingen stuurt, krijgt een eigen token op het account
`proxmox` (mag schrijven op het topic `homelab`). Zo trek je er één in zonder
de rest. Nu zijn dat er vijf: proxmox, pbs, unifi, vaultwarden en neogate.

<Steps>

#### Maak het token en versleutel het

```bash filename="laptop"
TOKEN=tk_$(LC_ALL=C tr -dc a-z0-9 </dev/urandom | head -c 29)
printf %s "$TOKEN" | ansible-vault encrypt_string --encrypt-vault-id infra \
  --stdin-name vault_ntfy_<app>_token
```

Zet de uitvoer in `inventory/group_vars/all/vault.yml`
(`ansible-vault edit`), of als los bestand ernaast zoals
`ntfy_neogate.yml`.

#### Zet het in de lijst

Voeg `'proxmox:' ~ vault_ntfy_<app>_token ~ ':<app>'` toe aan
`NTFY_AUTH_TOKENS` in `inventory/group_vars/proxmox/lxcs.yml`, dan:

```bash filename="laptop"
ansible-playbook playbooks/proxmox-oci.yml --check   # "env would be set"
ansible-playbook playbooks/proxmox-oci.yml           # ntfy herstart even
```

#### Test

```bash filename="laptop"
curl -H "Authorization: Bearer $TOKEN" -d test https://ntfy.neodata.be/homelab
```

Geeft `200`. Geef de app daarna `https://ntfy.neodata.be/homelab` en het token.

</Steps>

## Goed om te weten

### Waarom anders dan een gewone container

- **Geen `new-guest.yml`**: er is geen SSH, dus geen bootstrap en geen
  baseline. De tag `oci` houdt hem buiten `linux`, anders zou `site.yml` er
  vergeefs de baseline op proberen.
- **Proxmox negeert `entrypoint` en `env` bij het aanmaken** en neemt die van
  het image over. Daarom zet de rol ze er achteraf op, en herstart hij de
  container als ze veranderen: env wordt alleen bij het starten gelezen.
- **`env` gaat via de API, niet via `pct`**: Proxmox wil de variabelen
  gescheiden door NUL-tekens, en een shell kan die niet doorgeven. Alles plakt
  dan aan elkaar, `PATH` verdwijnt, en de container stopt zonder uitleg. Wie
  `env` zet, vervangt trouwens alles, ook de `PATH` van het image; de rol zet
  die daarom altijd zelf mee.
- **Het image ophalen gebeurt als root**, alles daarna met de API-token van
  Ansible. Ophalen vraagt het recht om pve01 van eender waar te laten
  downloaden, en dat hoort die token niet te hebben voor één `pull`.

### Updaten is opnieuw bouwen

Een herbouw sloopt de container **en zijn volumes**. Daarom staat alles wat
moet overleven in `env`: voor ntfy zijn dat de gebruikers, rechten en tokens,
die er na de start meteen weer zijn. Je verliest alleen de berichtcache van de
laatste uren.

### `printf %s`, niet `echo`

Een newline op het einde komt mee in het token, en Proxmox weigert dan de hele
env met `400 Parameter verification failed`. De oude tokens blijven werken,
het nieuwe niet.

### `--encrypt-vault-id infra`

Verplicht: er zijn twee vault-id's en `encrypt_string` kiest niet zelf.
