# Nieuwe container

Een extra container (LXC) op pve01, voor software die een eigen machine hoort
te hebben. Twijfel je tussen container en VM: kies de container. Die start in
een seconde, kost bijna geen geheugen, en alles gaat automatisch. Gewoon een
Docker-app? Dan heb je geen nieuwe machine nodig: [Dienst toevoegen](/docker/toevoegen/).

Voorbeeld: Vaultwarden op een eigen LXC. [OpenTofu](/opentofu/) maakt de
container, Ansible zet hem klaar.

<Steps>

#### Zoek een vrij nummer

```bash filename="laptop"
ssh pve01 'sudo pvesh get /cluster/resources --type vm'   # elke guest: vmid, naam, status
```

Kies een nummer dat daar niet in staat, en niet `199` (de restore-drill).
Heeft het nummer nog oude back-ups in PBS, neem dan een ander
([waarom](#een-oud-nummer-hergebruiken)):

```bash filename="laptop"
ssh pve01 'sudo pvesm list pbs | grep /<nummer>/'   # moet leeg zijn
```

#### Zoek een vrij adres

Kijk in `tofu/proxmox/containers.tf` welke adressen al gebruikt worden, en
test of het adres echt vrij is:

```bash filename="laptop"
ping -c 2 192.168.0.31   # geen antwoord = waarschijnlijk vrij
```

#### Zet de container in `containers.tf`

```bash filename="laptop"
$EDITOR tofu/proxmox/containers.tf
```

Voeg in `local.containers` een blok toe, naast de andere:

```hcl filename="tofu/proxmox/containers.tf"
    vaultwarden = {
      vm_id        = 111
      cores        = 1
      memory       = 512
      swap         = 512
      disk         = { datastore = "vm-hdd", size = 8 }
      ip           = "192.168.0.31/24"
      ipv6_auto    = false
      mac          = null
      keyctl       = false
      dns_servers  = ["192.168.0.29"]
      searchdomain = local.guest_network.searchdomain
      tags         = []
    }
```

| Veld | Wat je invult |
| --- | --- |
| de naam (`vaultwarden`) | kleine letters, geen spaties. Wordt ook zijn naam in de inventory |
| `vm_id` | het vrije nummer |
| `cores` / `memory` / `swap` | geheugen in MB. Begin klein, ophogen kan later |
| `disk` | opslag + grootte in GB. `vm-hdd` voor gewone dingen, `local-lvm` als het snel moet |
| `ip` | het vrije adres, met `/24` erachter |
| `mac` | `null`: dan kiest Proxmox er een. Zet hem na het bouwen vast (zie hieronder) |
| `dns_servers` / `searchdomain` | laten zoals in het voorbeeld: AdGuard als DNS, `home.arpa` als zoekdomein |
| `keyctl` | `false`. Docker in de container? Zie [Docker in een container](#docker-in-een-container-keyctl) |

Gateway, template en de Ansible-sleutel staan één keer onderaan hetzelfde
bestand. Die hoef je niet in te vullen.

#### Kijk wat OpenTofu gaat doen

```bash filename="laptop"
bin/tofu proxmox plan
```

Onderaan moet `1 to add, 0 to change, 0 to destroy` staan. Staat er iets
anders, stop en kijk eerst wat er nog verandert.

#### Maak de container

```bash filename="laptop"
bin/tofu proxmox apply
```

Hij toont het plan nog een keer; typ `yes`. De container staat er nu, met de
Ansible-sleutel in root.

#### Zet hem klaar met Ansible

```bash filename="laptop"
ansible-playbook playbooks/new-guest.yml -e guest=vaultwarden
```

Dit wacht tot SSH luistert, vertrouwt zijn hostkey, zet het `ansible`-account
erop en past de baseline toe. Aan het eind staat in beeld wat je hierna doet.

#### Zet het MAC-adres vast

```bash filename="laptop"
ssh pve01 'sudo pct config 111 | grep net0'   # hwaddr=BC:24:11:...
```

Zet dat MAC in plaats van `null` bij `mac`, en draai `bin/tofu proxmox plan`:
dat moet nu `No changes` zeggen. Zo krijgt een herbouw hetzelfde MAC, en dus
hetzelfde adres in UniFi.

#### Commit en push

```bash filename="laptop"
git add tofu/proxmox/containers.tf
git commit -m "feat: vaultwarden container"
git push
```

#### Werk hem af

De machine staat er, maar is nog leeg: ga verder met
[Afwerken](/proxmox/afwerken/).

</Steps>

## Goed om te weten

### Waar het adres van een container vandaan komt

Het adres staat in `tofu/proxmox/containers.tf`; OpenTofu zet het bij het
maken op de container. Daarna haalt de inventory het live uit Proxmox. Je
schrijft het adres dus nergens anders op, en zet een guest **nooit** in
`00-static.yml`: dat overschaduwt de live gegevens.

### Waarom OpenTofu voor de machines

OpenTofu onthoudt wat het gemaakt heeft, en toont eerst een plan: wat erbij
komt, wat verandert, wat weg zou gaan. Pas na `yes` gebeurt er iets. Zet je
`memory` hoger, dan toont het plan dat meteen. Meer:
[OpenTofu](/opentofu/#pbs-bewaart-de-inhoud-opentofu-de-vorm).

### Waarom de hostkey via Proxmox gelezen wordt

Een nieuwe container heeft een hostkey die niemand kent, en Ansible kan die
niet zomaar accepteren. `new-guest.yml` leest de sleutel via `pct exec`
rechtstreeks van de schijf van de container. Zo vertrouw je de echte machine,
en niet wat er toevallig op dat adres antwoordt.

### Docker in een container: `keyctl`

Een nieuwe container met `keyctl = true` lukt niet via OpenTofu: Proxmox laat
elke flag behalve `nesting` alleen `root@pam` zetten, ook bij het aanmaken, en
OpenTofu werkt met een token. Maak hem dus met `keyctl = false`, zet de flag
als root op pve01 (`pct set <id> --features nesting=1,keyctl=1`), en zet
daarna `true` in `containers.tf` tot het plan leeg is.

### Een oud nummer hergebruiken

Een nieuwe guest met een nummer dat nog back-ups in PBS heeft, komt in
dezelfde back-upgroep, en de opruimregels gooien dan de oude back-ups weg.
