# Afwerken

Je [container](/proxmox/container/) of [VM](/proxmox/vm/) staat er en heeft
de baseline. Nu de rest: de dienst erop, een adres, de back-up en de docs.
Voorbeeld: `vaultwarden`.

<Steps>

#### Installeer de dienst

Voor software zonder Docker schrijf je een rol. Dat staat in
[Eigen rol](/ansible/rol/).

#### Geef hem een adres (optioneel)

Wil je hem op `https://vaultwarden.neodata.be`, zet dan een route in
`inventory/host_vars/caddy/main.yml` onder `caddy_sites`:

```yaml filename="inventory/host_vars/caddy/main.yml"
  - { name: vaultwarden, host: vaultwarden, port: 8080, desc: "Wachtwoordkluis" }
```

```bash filename="laptop"
ansible-playbook playbooks/caddy.yml
ansible-playbook playbooks/smoketest.yml --tags caddy
```

Alle velden van een route: zie [Alle velden van een route](/netwerk/caddy/#alle-velden-van-een-route).

#### Commit en push

```bash filename="laptop"
git add inventory/ roles/ playbooks/
git commit -m "vaultwarden erbij"
git push
```

Semaphore draait vanuit git: een route of rol die niet gepusht is, bestaat
voor Semaphore niet.

#### Controleer

```bash filename="laptop"
ansible-playbook playbooks/site.yml --check --diff --limit vaultwarden
```

Een dry run: staat er niets open, dan klopt alles.

#### Werk de docs bij

```bash filename="laptop"
ansible-playbook playbooks/docs.yml
```

[Machines](/homelab/machines/) wordt uit de inventory gemaakt: zonder deze
stap staat je nieuwe machine er niet op.

</Steps>

## Als het misgaat

| Wat je ziet | Wat het is |
| --- | --- |
| `new-guest.yml` stopt meteen met een lijst namen | Proxmox kent die naam niet: de container bestaat nog niet. Zet hem in `tofu/proxmox/containers.tf`, draai `bin/tofu proxmox apply` en dan opnieuw |
| `bin/tofu proxmox plan` zegt `must be replaced` | OpenTofu wil de machine weggooien en leeg opnieuw maken. **Nooit** `apply` doen. Meestal staat er een veld in de `.tf` dat Proxmox anders heeft (template, opslag). `prevent_destroy` houdt het tegen, maar zoek de oorzaak |
| `bin/tofu proxmox plan` wil iets terugzetten dat je in het Proxmox-scherm veranderde | Het `.tf`-bestand wint. Zet de waarde daar, zie [Machine aanpassen](/proxmox/beheren/#een-machine-aanpassen) |
| Het blijft hangen bij "Wait for SSH" (3 minuten) | De container start niet, of het adres klopt niet. Kijk in het Proxmox-scherm of hij draait en welk adres hij heeft |
| Een fout over een hostkey | Er stond al een andere machine op dat adres. `ssh-keygen -R <adres>` en opnieuw |
| Een fout over het vault-wachtwoord | `~/.ansible/vault_pass_infra` ontbreekt of klopt niet, zie [Laptop klaarzetten](/ansible/laptop/) |
| Een VM staat niet in de inventory | De guest agent draait niet. Zie [Nieuwe VM](/proxmox/vm/#controleer-dat-ansible-hem-ziet) |
| Een OCI-container staat meteen weer op `stopped` | Meestal een ontbrekend `entrypoint`-argument of een map die niet bestaat. Zet `lxc.console.logfile: /tmp/ct.log` onderaan `/etc/pve/lxc/<vmid>.conf`, start hem, en lees dat bestand. Haal de regel daarna weer weg |

Een half klaargezette container is niet erg: `new-guest.yml` mag altijd
opnieuw. Wat al klaarstaat wordt niet nog eens gedaan.
