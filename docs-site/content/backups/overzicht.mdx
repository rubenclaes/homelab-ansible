# Back-ups

Drie kopieën: elke nacht naar PBS, elke week naar de Mac mini, elke nacht
het belangrijkste naar Cloudflare R2. Hier staat wat waar staat, wat je
**nu al** moet doen zodat terugzetten later lukt, en hoe je test dat het
werkt. Iets stuk? Kies links onder **Als het stuk is**.

## Waar de back-ups staan

| | Dagelijks | Wekelijks | Buiten het huis |
| --- | --- | --- | --- |
| Wanneer | elke nacht 02:30 | zondag 01:00 | elke nacht 04:00 |
| Waarheen | PBS (`pbs`), op pve01 zelf | de Mac mini (`macmini-backup`) | Cloudflare R2 |
| Wat | alle guests behalve 100 (PBS) en 110 (LANCache) | 101, 102, 103, 104, 106, 107, 108 | alleen wat git niet kan herbouwen, zie [Terughalen uit R2](/backups/r2/) |
| Hoe | incrementeel, gededupliceerd | volledige `.tar.zst`/`.vma.zst`-dumps | kopie van PBS, door `r2-guard` |
| Bewaart | 7 | 2 | 3 |
| Versleuteld | ja | **nee** | ja |
| Redt je van | een kapotte guest | een pve01 die weg is | een huis dat weg is |
| Terugzetten | [Een guest terugzetten](/backups/terugzetten/) | [Tweede kopie](/backups/tweede-kopie/) | [Terughalen uit R2](/backups/r2/) |

Daarnaast maakt `docker` om 02:00 zelf een back-up van zijn app-data en
foto's naar PBS (`docker-data-backup.timer`); die gaat mee naar R2. Bron:
`inventory/group_vars/proxmox/backup.yml` en `storage.yml`, en `pbs_offsite`
in `inventory/host_vars/pbs/main.yml`.

Een mislukte back-up meldt zich via ntfy, een geslaagde niet
([Meldingen](/homelab/diensten/ntfy/#meldingen-op-je-iphone)).

## Vooraf: doe dit nu

Doe dit terwijl alles nog werkt. Achteraf kan het niet meer.

<Steps>

#### Maak een papieren kopie van de twee PBS-sleutels

```bash filename="laptop"
ssh pve01 'sudo proxmox-backup-client key paperkey /etc/pve/priv/storage/pbs.enc --output-format text'
ssh docker 'sudo proxmox-backup-client key paperkey /root/.config/proxmox-backup/docker-data.key --output-format text'
```

De eerste is de sleutel van alle guests, de tweede die van de app-data en
foto's van `docker`. Print beide en bewaar ze **buiten het huis**. Zonder deze
sleutels zijn de back-ups op PBS en in R2 niet terug te zetten.

#### Bewaar de twee vault-wachtwoorden op dezelfde plek

```bash filename="laptop"
cat ~/.ansible/vault_pass_infra
cat ~/.ansible/vault_pass_stacks
```

Ze openen alles wat de repo versleuteld bewaart: API-tokens, logins, de
`.env`-bestanden van de stacks. Ze staan met opzet niet in git.

</Steps>

## Testen dat terugzetten werkt

Een herstelpad dat nooit gedraaid heeft, is een aanname.

```bash filename="laptop"
ansible-playbook playbooks/restore-drill.yml -e drill_confirm=true
```

Zet de nieuwste back-up van één container terug op vmid 199, leest er een
bestand uit, en sloopt 199 weer. Zo weet je dat de sleutel werkt en het
archief heel is. Alleen containers: een teruggezette VM zou met het origineel
botsen op MAC en IP.
Semaphore draait hem elke maand
([schema](/semaphore/#wat-draait-er-vanzelf-en-wanneer)); met de hand na een
wijziging aan de back-upjobs.

| Wil je | Zet erachter |
| --- | --- |
| een bepaalde guest (standaard kiest hij zelf een container) | `-e guest=<naam>` |
| alleen zien welke back-up hij zou pakken | `--check` |

**Faalt de drill, dan blijft 199 staan**, zodat je kan kijken wat er misging.
Opruimen: `ssh pve01 'sudo pct destroy 199'`.

Het bouwpad (`bin/tofu proxmox apply`, `new-guest.yml`, de baseline) test je
gewoon door het te gebruiken: elke nieuwe container loopt het van begin tot
eind.

## De R2-sync weer aanzetten

Je kreeg de melding **"R2-sync gestopt"** (of elke nacht "R2-sync staat nog
stil"). `r2-guard` start de kopie naar R2 niet meer, zodat het nooit geld
kost ([waarom](#waarom-r2-zo-voorzichtig-is)). Er gaat niets naar R2 tot jij
hem weer aanzet.

<Steps>

#### Lees waarom

```bash filename="laptop"
ssh pbs 'sudo cat /var/lib/r2-guard/stopped'
```

| Reden | Wat doen |
| --- | --- |
| "r2-guard faalde" of "Cloudflare gaf fouten" | het Cloudflare-token werkt niet (verlopen, ingetrokken), of Cloudflare had een storing. Nieuw token nodig? Account Analytics: Read, in `inventory/host_vars/pbs/vault.yml` als `vault_cf_analytics_token`, dan `ansible-playbook playbooks/pbs.yml --tags offsite` |
| boven 8 GB | er staat te veel in R2, meestal door de foto's: zie de volgende stap |
| te veel operaties | ongewoon: kijk in Cloudflare → R2 → Metrics wat er zo vaak gebeurde |

#### Te vol: minder versies bewaren

```bash filename="laptop"
ssh pbs 'sudo proxmox-backup-manager prune-job update offsite-prune --keep-last 2'
ssh pbs 'sudo proxmox-backup-manager sync-job update offsite-r2 --transfer-last 2'
```

De jobs staan al in PBS, dus `keep_last` in de inventory aanpassen verandert
ze niet: doe het met de hand, en pas daarna de inventory aan. R2 wordt pas
kleiner na de prune **en** de garbage collection daarna (allebei dagelijks).

#### Meet, dan pas weer aan

```bash filename="laptop"
ssh pbs 'sudo rm /var/lib/r2-guard/stopped && sudo /usr/local/sbin/r2-guard --dry-run'
```

Je ziet `R2: … GB …` en `(dry-run, geen sync)`, geen STOP: de sync loopt
vannacht weer. Staat er toch STOP, dan is hij al opnieuw gestopt: terug naar
de eerste stap.

</Steps>

## Goed om te weten

### Papier, niet de wachtwoordkluis

Vaultwarden draait zelf in de homelab. Brandt het huis af, dan zit hij in R2,
achter precies deze sleutels. Bewaar de sleutels en de vault-wachtwoorden dus
samen, op papier. `proxmox-backup-client key show` toont alleen de
fingerprint: daar kan je niets mee terugzetten.

Vault-wachtwoorden kwijt? Dan is de repo compleet maar onbruikbaar: bijna elk
playbook leest een vault-bestand. De enige weg terug is elk vault-bestand
opnieuw maken en elk secret opnieuw zetten.

### Waarom de dagelijkse niet genoeg is

De dagelijkse staat op pve01 zelf: sterft die machine met zijn schijven, dan
gaan guests en back-ups samen. Daarvoor is de wekelijkse op de Mini, en voor
brand of diefstal de kopie in R2. De dumps op de Mini zijn niet versleuteld:
wie die NFS-share kan mounten, kan ze lezen. Die in R2 wel.

### Waarom maar twee dumps op de Mini

`media01` op de Mini is bijna vol en draagt ook Time Machine. Daarom staat
`prune-backups keep-last=2` op de opslag (ongeveer 50 GB). Wil je meer, kijk
dan eerst `df` op de Mini: loopt die schijf vol, dan breken beide back-ups
tegelijk.

### De wekelijkse job nakijken

Slaapt de Mini op zondagnacht, of is de share weg, dan faalt de job, en
krijg je een melding. Zelf kijken:

```bash filename="laptop"
ssh pve01 'sudo pvesm list macmini-backup'
ssh pve01 'df -h /mnt/pve/macmini-backup'
```

### Een nieuwe guest in de wekelijkse

De dagelijkse naar PBS neemt elke guest vanzelf mee, de wekelijkse niet: die
heeft een vaste lijst. Zie [Afwerken](/proxmox/afwerken/#zet-hem-in-de-wekelijkse-back-up).

### Waarom R2 zo voorzichtig is

R2 moet binnen de gratis 10 GB blijven, en Cloudflare kent geen harde
uitgavengrens. Ansible dwingt dit af: komt er een schema of `remove-vanished`
bij, dan haalt de volgende run het weg.

| Keuze | Waarom |
| --- | --- |
| alleen r2-guard start de sync, de job heeft geen schema | r2-guard checkt eerst; bij twijfel of een crash gaat er die nacht niets heen |
| stop boven 8 GB, 800.000 Class A- of 8.000.000 Class B-operaties per maand; waarschuwing vanaf 6,5 GB | wat één nacht uploadt, weet hij pas achteraf. De 2 GB onder de gratis 10 GB vangt een drukke nacht op |
| r2-guard telt de bucket zelf | de cijfers van Cloudflare lopen tot een dag achter |
| nooit wissen in R2 (`remove-vanished` uit) | anders wist een lege `store1` (na een herbouw of ransomware) alles in R2, net als je het nodig hebt. Oude versies ruimt de prune job op |
