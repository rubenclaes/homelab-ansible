# pve01 opnieuw: back-ups

Deel 2 van 3, na [pve01 zelf](/backups/pve01/). PBS is VM 100 en draait op
pve01 zelf. Hij moet dus bestaan vóór je zijn opslag kan koppelen.

<Steps>

#### Maak `vm-hdd` bekend in Proxmox

In het Proxmox-scherm: Datacenter → Storage → Add → ZFS.

| Veld | Waarde |
| --- | --- |
| ID | `vm-hdd` |
| ZFS Pool | `vm-hdd` |
| Content | Disk image, Container |

De pool is geïmporteerd, maar Proxmox weet nog niet dat hij hem mag gebruiken.
De PBS-datastore staat op die pool.

#### Maak de PBS-VM (100) met de hand

Exact volgens het blok `pbs` in `tofu/proxmox/vms.tf`: cores, geheugen,
schijven en MAC-adres. **Niet** met `bin/tofu proxmox apply`: die zou `scsi1`
als nieuwe, lege schijf maken.

- **MAC-adres overnemen** (`BC:24:11:3D:B4:6A`): daar hangt de DHCP-reservering aan.
- Systeemschijf `scsi0`: nieuw, 32G op `local-lvm`.
- Datastore `scsi1`: **niet nieuw maken**. Koppel de bestaande schijf terug:

```bash filename="pve01"
qm rescan --vmid 100     # vindt de oude schijf op vm-hdd als 'unused'
```

Hang die daarna in het scherm aan als `scsi1`, met backup uit.

<Callout type="error">
`scsi1` ís de datastore met al je back-ups. Een nieuwe 320G-schijf maken =
een lege datastore. Je back-ups staan op de oude schijf, nergens anders. Dit
stuk is nog nooit gelopen; ga langzaam.
</Callout>

#### Installeer PBS in de VM

Van de PBS-ISO: haal de nieuwste van
[proxmox.com/downloads](https://www.proxmox.com/en/downloads) via **local →
ISO Images → Download from URL**, en hang hem aan als CD/DVD. De oude
systeemschijf stond op `local-lvm` en is met de herinstallatie verdwenen.

Zorg daarna dat de datastore van `scsi1` weer op `/mnt/datastore/store1`
hangt, vóór `pbs.yml` draait: vindt de rol geen `store1`, dan maakt hij er een
nieuwe, lege aan.

#### Breng PBS onder Ansible

```bash filename="laptop"
ssh-keygen -R <pbs-adres>
ansible-playbook playbooks/bootstrap.yml --limit pbs -u root -k
ansible-playbook playbooks/pbs.yml
```

De inventory vindt het adres van een VM via de guest-agent (`agent` in
`tofu/proxmox/vms.tf`). Geen agent in de VM = geen adres = Ansible vindt `pbs` niet.

#### Koppel PBS in Proxmox

Met de hand: Datacenter → Storage → Add → Proxmox Backup Server.

- ID: **`pbs`** (de back-upjob en de drills verwachten die naam)
- datastore `store1`, gebruiker `pve@pbs` met zijn wachtwoord (niet in de repo; kwijt? zet een nieuw in het PBS-scherm)
- de **encryptiesleutel** (je papieren kopie)

Dit staat met opzet in geen playbook: de definitie draagt de
encryptiesleutel, en die hoort niet in git.

#### Maak de map voor de tweede kopie

Op de **Mac mini**:

```bash filename="laptop"
ssh rubenclaes@192.168.0.26 "mkdir -p '/Volumes/media01/backups/proxmox'"
```

Een NFS-export laat zich niet mounten op een pad dat er niet is. Zonder deze
map komt `macmini-backup` er wel, maar blijft hij inactief.

#### Zet de overige opslag en de back-upjobs terug

```bash filename="laptop"
ansible-playbook playbooks/proxmox-datacenter.yml -e proxmox_datacenter_create=true
```

Maakt `macmini-backup` en de twee back-upjobs uit
`inventory/group_vars/proxmox/storage.yml` en `backup.yml`. Alleen hier de flag
`-e proxmox_datacenter_create=true`, zie
[waarom](#waarom-proxmox_datacenter_create-niet-standaard-aan-staat).

#### Trek pve01 gelijk

```bash filename="laptop"
ansible-playbook playbooks/site.yml --limit pve01
```

Pas nu: `site.yml` controleert ook de opslag, en stopt met "Not found on the
node" zolang die er niet is.

</Steps>

Klaar? Ga verder met [de machines](/backups/pve01-machines/).

## Goed om te weten

### Waarom `proxmox_datacenter_create` niet standaard aan staat

Op een gezonde node betekent ontbrekende opslag: "de inventory klopt niet". Op
een herbouwde node: "de inventory is de waarheid, maak het aan". Alleen jij
weet welke van de twee het is. Daarom zet je de flag zelf, en alleen bij een
herbouw.
