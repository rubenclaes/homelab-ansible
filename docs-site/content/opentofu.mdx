# OpenTofu

OpenTofu beheert de dingen die geen Ansible zijn: de **machines op pve01**
(welke er zijn en hoe groot), de **Tailscale-regels** (wie mag waar, de DNS
en de tags van de tailnet) en de **apps die via Pocket ID inloggen**. De bestanden staan in `tofu/`, één map per
systeem, en je draait alles via `bin/tofu`.

Elke keer dezelfde twee stappen: `plan` toont wat er zou veranderen, `apply`
doet het, pas na `yes`.

`backend.tf`, `providers.tf` en `versions.tf` zeggen waar de state staat en
waarmee OpenTofu praat; daar kom je zelden aan. `secrets.env` is versleuteld
(vault `infra`).

## Tailscale-regels aanpassen

Wie op de tailnet waar mag komen, staat in `files/tailscale/policy.hujson`.
OpenTofu zet dat bestand in Tailscale. In de console kan je de regels niet
meer aanpassen: git is de enige weg.

<Steps>

#### Eenmalig op een nieuwe computer

OpenTofu installeren en de vault-wachtwoorden neerzetten zoals in de README,
dan:

```bash filename="laptop"
brew install opentofu
bin/tofu tailscale init
bin/tofu proxmox init
```

#### Pas het bestand aan

`files/tailscale/policy.hujson`. Zet bij een nieuwe regel ook een regel in
`tests`: wie mag erbij en wie niet. Dan weigert Tailscale een fout in plaats
van hem stil door te laten.

#### Kijk wat er zou veranderen

```bash filename="laptop"
bin/tofu tailscale plan
```

Alleen `tailscale_acl.this` mag veranderen. Staat er iets anders? Stop en
zoek eerst uit waarom.

#### Doen

```bash filename="laptop"
bin/tofu tailscale apply
```

Faalt het met `test(s) failed`: een regel en een test spreken elkaar tegen.
Er is dan niets veranderd.

#### Commit en push

`policy.hujson` is de bron. Een wijziging die niet in git staat, bestaat
niet.

</Steps>

Ook de DNS van de tailnet (adguard als nameserver), de goedgekeurde route van
ct 108 en de tag van adguard staan zo in `tofu/tailscale/`. Zelfde stappen.

## Een app via Pocket ID laten inloggen

Welke apps via [id.neodata.be](https://id.neodata.be) mogen inloggen, staat in
`tofu/pocketid/clients.tf`: één `pocketid_client` per app. De groepen staan in
`groups.tf`:

| Groep | Wie |
| --- | --- |
| `admin` | wie het homelab beheert |
| `gezin` | wie hier woont |
| `familie` | ouders, broers en zussen |

Elke client zegt met `allowed_user_groups` welke groepen erin mogen. Clients
en groepen maak je dus niet in de UI. Gebruikers, wie in welke groep zit, en
passkeys wel: die beheert OpenTofu bewust niet, zodat een apply nooit iemand
weghaalt die daar net is toegevoegd.

<Steps>

#### Zet de client erbij

Kopieer het blok van `outline` in `clients.tf`. Pas `name`, `client_id`,
`launch_url`, de callback-URL (die staat in de docs van de app) en
`allowed_user_groups` aan, en voeg een `output` voor het secret toe.

#### Plan en apply

```bash filename="laptop"
bin/tofu pocketid plan
bin/tofu pocketid apply
```

#### Zet het secret in de .env van de app

```bash filename="laptop"
bin/tofu pocketid output -raw <app>_client_secret
ansible-vault edit files/env/<app>.env
```

Pocket ID geeft het secret alleen bij het aanmaken. Het staat daarna enkel in
de versleutelde state, en `output` haalt het daar op.

</Steps>

OpenTofu praat rechtstreeks met `192.168.0.15:1411`, niet via Caddy, met de
`STATIC_API_KEY` van Pocket ID (`POCKET_ID_STATIC_API_KEY` in
`files/env/infra.env`, en als `POCKETID_API_TOKEN` in `tofu/secrets.env`).
Daardoor bestaat er geen sleutel die eerst iemand in de UI moet aanmaken.

<Callout type="error">
Zegt een plan dat een client **`must be replaced`**, dan krijgt die app een
nieuw secret. Na de apply moet dat meteen in zijn `.env`, anders kan niemand
meer inloggen.
</Callout>

## De machines op pve01

`tofu/proxmox/` beschrijft de guests op pve01 en de Proxmox-gebruiker van
Ansible. Wat hier staat, verander je hier, niet in het Proxmox-scherm: het
volgende plan zou je wijziging daar weer terugzetten.

| Bestand | Wat erin staat |
| --- | --- |
| `vms.tf` | de VM's 100 `pbs`, 101 `haos`, 102 `docker-grafana-stack`, 103 `docker`: één blok per VM |
| `containers.tf` | de Debian-containers 104 `semaphore`, 106 `caddy`, 107 `adguard`, 108 `tailscale`: één regel per container in `local.containers`, plus het template en de Ansible-sleutel voor nieuwe containers |
| `access.tf` | de gebruiker `ansible@pve`, zijn rol `AnsibleAutomation` en zijn rechten |
| `oidc.tf` | inloggen via Pocket ID: de realm `pocketid`, de groep `admin-pocketid` en zijn rechten (Administrator) |

```bash filename="laptop"
bin/tofu proxmox plan    # wat zou er veranderen?
bin/tofu proxmox apply   # doe het (typ yes)
```

Wat je ermee doet: [een container maken](/proxmox/container/),
[een VM maken](/proxmox/vm/), [een guest aanpassen of weghalen](/proxmox/beheren/).

<Callout type="error">
Zegt een plan **`must be replaced`**, doe dan nooit `apply`. Vervangen
betekent: de machine weggooien en leeg opnieuw maken. Elke guest heeft
`prevent_destroy`, dus OpenTofu weigert het ook zelf, maar zoek de oorzaak.
</Callout>

**Bewust niet in OpenTofu:**

| Wat | Waar dan |
| --- | --- |
| `tofu@pve` zelf, de gebruiker van OpenTofu | met de hand, zie [pve01 is weg](/proxmox/pve01/#maak-de-gebruiker-van-opentofu) |
| `root@pam` en `rubenclaes@pam` | met de hand; wie Proxmox beheert, hoort niet van een tool af te hangen. `root@pam` is ook de noodtoegang als Pocket ID plat ligt |
| wie er via Pocket ID binnenkomt (`rubenclaes@pocketid`) | Proxmox maakt die bij de eerste login; de groep komt uit Pocket ID |
| `ntfy` (ct 109), de OCI-container | `pve_oci_lxcs` en `roles/proxmox_oci`, zie [OCI-container](/proxmox/oci/#een-oci-container) |
| opslag, back-upjobs, meldingen, netwerk van pve01 | Ansible (`proxmox-datacenter.yml`) |
| `/dev/net/tun` voor 107 en 108 | Ansible als root (`roles/proxmox_tun`): een API-token mag dat niet |

### Na een ramp: eerst PBS, dan OpenTofu

**Zet eerst alles terug uit PBS, dan pas `bin/tofu proxmox plan`.** OpenTofu
weet na een ramp nog welke guests er horen, en een `apply` zou ze leeg opnieuw
maken. Waarom en hoe: [pve01 opnieuw opbouwen](/proxmox/pve01/#deel-3--de-machines-en-diensten).

## Goed om te weten

### PBS bewaart de inhoud, OpenTofu de vorm

Een back-up in PBS is de schijf van een guest: alles wat erop staat. OpenTofu
kent de vorm: cores, geheugen, schijfgrootte, adres, MAC. Samen krijg je een
guest precies terug. Vroeger maakte Ansible de containers, maar alleen als ze
ontbraken; een bestaande guest raakte het nooit aan. Nu toont elk plan het
meteen als Proxmox en de repo uit elkaar lopen.

### Waarom OpenTofu en niet de console

Git beslist: elke wijziging heeft een diff en een reden, en `plan` toont
vooraf wat er gebeurt. OpenTofu houdt bij wat hij beheert in een state. Die
staat versleuteld in Cloudflare R2, niet op de homelab: ligt pve01 plat, dan
weet OpenTofu nog wat er moet staan. De geheimen staan in `tofu/secrets.env`
(vault `infra`); de passphrase van de state staat ook in Vaultwarden, want
zonder is de state onleesbaar.

### Noodgeval zonder laptop

Zet in de Tailscale-console **Prevent edits in the admin console** even uit,
pas de regels aan, en zet het daarna terug aan. Thuis: `policy.hujson`
gelijkzetten tot `bin/tofu tailscale plan` leeg is, en committen.
