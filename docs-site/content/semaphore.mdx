# Semaphore

Semaphore draait playbooks vanzelf, op een schema. Hier zie je wat er loopt
en wanneer, en hoe je een schema aanpast.

## Wat draait er vanzelf, en wanneer?

Tijden zijn lokale tijd (Europe/Brussels).

### In Semaphore, met schema

| Template | Wanneer | Waarom dan |
| --- | --- | --- |
| UniFi watch | elk kwartier | meldt een toestel dat niet in `unifi_known_macs` staat |
| Stacks | dagelijks 05:30 | ná de converge van zondag, vóór Drift check |
| Drift check | dagelijks 06:00 | je ziet wat er tussen twee converges afwijkt |
| UniFi routes | dagelijks 06:15 | wijst elke route naar een toestel met een Fixed IP, en deelt UniFi de juiste DNS uit? |
| Smoketest | dagelijks 06:30 | tussen Drift check en Docs; twee jobs op dezelfde minuut vechten om dezelfde controller. Rood ook als een certificaat minder dan 14 dagen heeft |
| OpenTofu drift | dagelijks 06:45 | `plan` voor `tofu/tailscale`, `tofu/proxmox` en `tofu/pocketid`; rood als iets afwijkt van git |
| Backup check | dagelijks 07:15 | na de back-ups van 02:00 en 02:30; rood als een guest een nacht mist, of een week op de Mac mini |
| Docs | dagelijks 07:00 | de site volgt de repo |
| Cleanup (Apply) | zaterdag 03:00 | zonder deze ruimt de rapportageversie nooit iets op |
| Update guests | zondag 04:00 | een uur vóór de converge, zodat die de nasleep opruimt |

### In Semaphore, zonder schema (klik ze zelf)

| Template | Doet |
| --- | --- |
| Baseline (dry run) | `baseline.yml --check --diff`: verandert niets |
| Update pve01 | `update.yml --limit pve01`: pakketten op de hypervisor, zonder herstart. Als `UpdatesPending` afgaat |
| Caddy | `caddy.yml` |
| Cleanup (report) | rapporteert wat er vrij kan, verwijdert niets |

Daarmee staan alle zeventien templates in git. Maak je er een in de UI, zet hem
dan ook in `semaphore_templates_list`, anders klopt die lijst niet meer en
geloof je hem ten onrechte. Hoe:
[Een schema in Semaphore aanpassen](#een-schema-in-semaphore-aanpassen).

### Niet in Semaphore

De back-ups draaien op de cron van Proxmox: zie
[Back-ups](/backups/overzicht/#waar-de-back-ups-staan).

Een job die faalt of een host niet bereikt, stuurt een melding naar
[ntfy](/homelab/diensten/ntfy/): "Semaphore: `<playbook>` faalde", met de host
en de taak. Een dry run (`--check`) meldt niets.
Proxmox en PBS melden wel, via [ntfy](/homelab/diensten/ntfy/).

## Een schema in Semaphore aanpassen

De templates en hun schema's staan in `semaphore_templates_list` in
`inventory/host_vars/semaphore/main.yml`. `playbooks/semaphore-templates.yml`
zet ze via de API in Semaphore.

<Steps>

#### Kijk eerst wat er in de UI staat

Open Semaphore en noteer de **exacte** naam van de template, met hoofdletters.

`name` is de sleutel waarop de rol zoekt: `Cleanup (apply)` in plaats van
`Cleanup (Apply)` maakt een **tweede** template in plaats van de bestaande te
wijzigen ([meer](#een-template-hernoemen)).

#### Pas de lijst aan

```bash filename="laptop"
$EDITOR inventory/host_vars/semaphore/main.yml
```

```yaml filename="inventory/host_vars/semaphore/main.yml"
- name: "Drift check"
  playbook: playbooks/drift.yml
  description: "Wat zou site.yml veranderen? Faalt als het antwoord niet 'niets' is."
  arguments: ["-e", "drift_fail=true", "-e", "drift_limit=all:!mbp:!semaphore"]
  schedule: "0 6 * * *"   # lokale tijd (Europe/Brussels)
```

Laat de limits staan. Waarom: zie
[De limits in de templates](#de-limits-in-de-templates).

#### Probeer eerst een dry run

```bash filename="laptop"
ansible-playbook playbooks/semaphore-templates.yml --check
```

Lees de output van *Report the templates that will change*. Staat een template die je wilde **wijzigen** onder
`create`? Dan wijkt de naam af. Stop en verbeter de naam.

#### Zet het echt

```bash filename="laptop"
ansible-playbook playbooks/semaphore-templates.yml
```

#### Commit en push

```bash filename="laptop"
git add inventory && git commit -m 'Semaphore: schema Drift check' && git push
```

#### Werk de lijst op de docs-site bij

Pas de tabel in [Wat draait er vanzelf, en wanneer?](#wat-draait-er-vanzelf-en-wanneer)
aan: die is met de hand geschreven.

</Steps>

Eerste keer op een nieuwe controller? De API-login staat in
`inventory/host_vars/semaphore/vault.yml` (`vault_semaphore_api_user`,
`vault_semaphore_api_password`): de lokale `admin`, niet je account via
Pocket ID, want dat heeft geen wachtwoord. Ontbreekt dat bestand, dan faalt de rol met
een melding. Hoe je het aanmaakt, staat bovenaan `main.yml` in die map.

### Wat de rol wel en niet doet

| Doet | Doet niet |
| --- | --- |
| templates aanmaken en bijwerken | templates verwijderen: wat je uit de lijst haalt, blijft in de UI staan, mét schema |
| de cron zetten | een gepauzeerd schema weer aanzetten |
| naam, playbook, argumenten, beschrijving | surveys, views, vaults en de flags onder *Advanced* |

`site.yml` draait `semaphore-templates.yml` ook mee, maar alleen als je hem
**met de hand en zonder limit** draait. De geplande `Site converge` slaat hem
over; zie
[Een schema herschrijft zichzelf niet](#een-schema-herschrijft-zichzelf-niet).

## Inloggen

Via [Pocket ID](https://id.neodata.be): knop **Pocket ID** op de loginpagina,
alleen voor de groep `admin`. Pocket ID vraagt elke keer opnieuw je passkey,
ook als je er al ingelogd bent: Semaphore kan alles op elke machine.

| Account | Wat |
| --- | --- |
| `rubenclaes` | via Pocket ID, admin. Zo log je gewoon in. |
| `admin` | lokaal, met wachtwoord (Vaultwarden). De noodtoegang, en de gebruiker waarmee `semaphore-templates.yml` de API gebruikt. |

Een nieuwe beheerder logt eerst in via Pocket ID; daarna maak je hem admin:

```bash filename="semaphore"
sudo -u semaphore semaphore user change-by-login \
  --config /etc/semaphore/config.json --login <naam> --admin
```

Het OIDC-deel staat in `roles/semaphore/files/config.json` (versleuteld,
onder `oidc_providers.pocketid`), de client in `tofu/pocketid/clients.tf`.

## Goed om te weten

### Semaphore en Pocket ID: geen PKCE, geen gedeeld mailadres

Semaphore stuurt geen PKCE mee, dus die staat voor zijn client in Pocket ID
uit. En het koppelt op mailadres, maar weigert een login als er een
**lokaal** account met hetzelfde adres bestaat ("conflicts with local user").
Daarom heeft de lokale `admin` het adres `admin@semaphore.local`, en niet dat
van een persoon. Rollen leest Semaphore niet uit de groepen: admin maken gaat
met de hand, zoals hierboven.

### De limits in de templates

- **`!semaphore`** — houdt een job van zijn eigen container af. Herstart
  Semaphore halverwege, dan is de job dood en weet je niet of hij af is. Die
  machine patch je met de hand.
- **`!mbp`** — `mbp` heeft `ansible_connection: local`. Vanuit Semaphore
  betekent dat "de container die de job draait", niet je MacBook. Die zit in
  `macs` en zou macOS-taken krijgen in een Debian-container. Aan je bureau
  klopt `mbp` wel; daar draai je zonder limit.
- **Geen limit** bij `Homelab Report`, met opzet. `report.yml` slaat de
  macOS-taken zelf over als hij geen Mac ziet. En `all` telt de impliciete
  `localhost` niet mee: met een kale `all:!mbp` is de run groen maar
  verschijnt er niets op report.neodata.be. Een limit die te veel wegsnijdt
  maakt een job niet rood, alleen stil.
- **`drift_limit`** in plaats van `--limit` bij `Drift check` — `drift.yml`
  draait zelf op `localhost`; een `--limit` zou die play raken, niet de
  dry run eronder.

### Een schema herschrijft zichzelf niet

`Site converge` draait met `--limit all:!mbp:!semaphore`, dus de play
`semaphore-templates.yml` in `site.yml` valt daar weg. Dat is met opzet: een
schema dat zijn eigen schema's herschrijft terwijl het draait, wil je niet.

### Waarom de tijden lokale tijd zijn

Zonder instelling leest Semaphore elke cron als UTC, en dan schuift alles een
uur mee met de zomertijd. De `semaphore`-rol zet daarom
`SEMAPHORE_SCHEDULE_TIMEZONE` (`Europe/Brussels`), als omgevingsvariabele en
niet in de gevaulte `config.json`, zodat je hem kunt nalezen.

### Waarom `Stacks` dagelijks draait

`restart: unless-stopped` helpt niet tegen een container die niet wil
starten. Een stack die ergens stilvalt, trekt zo binnen een dag bij.

### Een template hernoemen

`name` is de sleutel waarop de rol zoekt. Hernoem je hem alleen in
`semaphore_templates_list`, dan maakt de rol een tweede template en blijft de
oude staan, met zijn schema. Hernoem hem dus eerst in de UI, en draai dan
`semaphore-templates.yml --check`: de template moet onder `update` staan, niet
onder `create`.
